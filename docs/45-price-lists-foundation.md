# AENAON ERP — 9.5B.1 Υποδομή πολλαπλών τιμοκαταλόγων

## Σκοπός
Ασφαλής, επεκτάσιμη αποθήκευση πολλαπλών εμπορικών τιμοκαταλόγων ανά επιχείρηση, κατάστημα και κανάλι πωλήσεων, πριν την ανάπτυξη της οθόνης διαχείρισης και οποιασδήποτε φορολογικής έκδοσης.

## Σύντομη περιγραφή
Το 9.5B.1 προσθέτει **υποδομή Domain / EF Core / SQL Server**. Δεν δημιουργεί ακόμη σελίδα τιμοκαταλόγων, ενέργεια CLI δημιουργίας τιμών ή αυτόματη επιλογή τιμοκαταλόγου σε παραγγελίες.

Η βάση αποκτά δύο νέους πίνακες:
- `dbo.PriceLists`: ταυτότητα και πλαίσιο τιμοκαταλόγου.
- `dbo.PriceListItems`: τιμή προϊόντος ή υπηρεσίας ανά τιμοκατάλογο.

{% hint style="warning" %}
Η migration `20261113150000_PriceListsFoundation` **δεν πρέπει να εφαρμοστεί χωρίς επαληθευμένο backup, προεπισκόπηση και ρητή έγκριση**. Το PR δεν εκτελεί migration στη βάση `AenaonERP_Dev`.
{% endhint %}

## Αρχιτεκτονική και πεδία

### PriceLists
| Πεδίο | Περιγραφή |
|---|---|
| Id | Μοναδικό GUID τιμοκαταλόγου |
| TenantId | Υποχρεωτική επιχείρηση |
| StoreId | Προαιρετικό κατάστημα **της ίδιας επιχείρησης** |
| Code / Name | Μοναδικός κωδικός ανά επιχείρηση / περιγραφή |
| Channel | All, DineIn, Takeaway, Delivery, Retail, Online |
| Currency | EUR στο παρόν στάδιο |
| PricesIncludeVat | Ρητή ένδειξη τιμών με ή χωρίς ΦΠΑ |
| ValidFrom / ValidUntil | Έναρξη και προαιρετική λήξη ισχύος |
| IsActive | Ενεργός ή ανενεργός τιμοκατάλογος |

### PriceListItems
| Πεδίο | Περιγραφή |
|---|---|
| Id | Μοναδικό GUID εγγραφής |
| TenantId | Υποχρεωτική επιχείρηση |
| PriceListId | Τιμοκατάλογος της ίδιας επιχείρησης |
| CatalogItemId | Προϊόν/υπηρεσία της ίδιας επιχείρησης |
| UnitPrice | Μη αρνητικό ποσό `decimal(18,4)` |

Σύνθετα ξένα κλειδιά αποτρέπουν σύνδεση με άλλον tenant. Ο μοναδικός δείκτης `TenantId + PriceListId + CatalogItemId` αποτρέπει διπλή τιμή του ίδιου είδους μέσα σε έναν τιμοκατάλογο. Το `PricesIncludeVat` περιγράφει **μόνο την εμπορική σημασία** της τιμής και δεν αποτελεί φορολογική κατάταξη.

## Πριν την εγκατάσταση
1. Επιβεβαιώστε ότι έχετε την τελευταία έκδοση του `main` και **7 εφαρμοσμένες migrations**, χωρίς παλαιότερες εκκρεμότητες.
2. Ελέγξτε την έκδοση SQL Server και compatibility level 160.
3. Πάρτε και επαληθεύστε πλήρες backup του `AenaonERP_Dev`. Δοκιμάστε restore σε απομονωμένο περιβάλλον.
4. Ελέγξτε το PR, τα tests και την επίδραση της νέας σύνθετης μοναδικότητας του πίνακα `Stores`.

## Εγκατάσταση σε Development
Από PowerShell στον φάκελο του repository:

```powershell
git fetch origin
git switch feature/9-5b-1-price-lists-foundation
git pull --ff-only origin feature/9-5b-1-price-lists-foundation

dotnet restore AenaonERP.slnx --locked-mode
dotnet test AenaonERP.slnx --configuration Release --filter "TestCategory!=SqlServer"
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --dry-run
```

Το `--dry-run` ελέγχει μόνο το schema και **δεν πραγματοποιεί αλλαγές**. Η αναμενόμενη πρόοδος στην ήδη ενημερωμένη τοπική βάση είναι **7 εφαρμοσμένες / 1 εκκρεμής** migration.

{% hint style="danger" %}
Μην εκτελείτε την επόμενη εντολή πριν εγκριθεί η migration, επιβεβαιωθεί το backup και ολοκληρωθούν οι δοκιμές στο CI.
{% endhint %}

Εντολή που θα χρησιμοποιηθεί **μόνο μετά την έγκριση**:

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --apply --confirm-database AenaonERP_Dev
```

## Έλεγχοι μετά την εφαρμογή
Μετά από εγκεκριμένη εφαρμογή:

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --dry-run
```

Αναμένεται **8 εφαρμοσμένες / 0 εκκρεμείς** migrations.

Στο SQL Server Management Studio μπορείτε να εκτελέσετε **μόνο ανάγνωση**:

```sql
SELECT name FROM sys.tables
WHERE schema_id = SCHEMA_ID(N'dbo')
  AND name IN (N'PriceLists', N'PriceListItems')
ORDER BY name;

SELECT MigrationId
FROM dbo.__EFMigrationsHistory
ORDER BY MigrationId;
```

## Χρήση, δικαιώματα και CLI
Στο παρόν βήμα δεν υπάρχει χρήστης που να δημιουργεί τιμοκαταλόγους από GUI ή CLI. Η δημιουργία, ενημέρωση, δικαιώματα Owner/Manage, idempotency, ασφαλή endpoints και διαχείριση conflict θα υλοποιηθούν στην επόμενη φάση **9.5B.2** μέσω κοινών Application services.

Δεν επιτρέπονται απευθείας χειροκίνητα INSERT/UPDATE στο παραγωγικό SQL Server. Τα test δεδομένα εισάγονται μόνο στη χωριστή βάση του CI.

## Πότε χρησιμοποιείται και πότε όχι
Χρησιμοποιείται ως **schema foundation** για πολλές εμπορικές τιμές ανά προϊόν ή υπηρεσία, π.χ. λιανική και delivery, χωρίς να δεσμεύει τη μελλοντική πολιτική επιλογής τιμοκαταλόγου.

Δεν χρησιμοποιείται ακόμη για εκδόσεις παραστατικών, φορολογικό χαρακτηρισμό ή αποστολή δεδομένων.

## Συμβατότητα myDATA / IMPACT
- Οι `CatalogUnitOfMeasure` και `CatalogAccountingType` **δεν μετατρέπονται αυτόματα** σε κωδικούς myDATA ή παρόχου.
- Η οντότητα `FiscalTaxMappingRecord` διατηρεί ανεξάρτητα πεδία `MeasurementUnitId`, `MeasurementUnitEnId`, `VatCategoryId`, `IncomeCategoryId` και `IncomeTypeId`.
- Δεν γίνεται έκδοση παραστατικού, κλήση IMPACT ή έγκριση φορολογικής αντιστοίχισης.
- Πριν την έκδοση θα απαιτείται τεκμηριωμένος έλεγχος μονάδων, ΦΠΑ, χαρακτηρισμών, χρονικής ισχύος και δομής πραγματικού payload.

{% hint style="warning" %}
Το διάστημα ισχύος τιμοκαταλόγου δεν αποτελεί απόδειξη νόμιμου φορολογικού συνδυασμού. Επίσης, δεν έχει οριστεί ακόμη αυτοματοποιημένη προτεραιότητα όταν περισσότεροι τιμοκατάλογοι καλύπτουν το ίδιο κανάλι/κατάστημα/ημερομηνία.
{% endhint %}

## Troubleshooting
**Εκκρεμής migration:** Είναι αναμενόμενο έως την εγκεκριμένη εφαρμογή.

**Αποτυχία unique constraint:** Ελέγξτε κωδικούς τιμοκαταλόγων ανά επιχείρηση και διπλές τιμές για ίδιο είδος.

**Αποτυχία foreign key:** Ελέγξτε ότι `TenantId`, `StoreId`, `CatalogItemId` και `PriceListId` ανήκουν στην ίδια επιχείρηση.

**Μη έγκυρη τιμή:** Επιτρέπονται μόνο μη αρνητικές τιμές με έως τέσσερα δεκαδικά, εντός του επιτρεπτού ορίου της εφαρμογής.

**Αποτυχία migration:** Μη δοκιμάσετε επαναλαμβανόμενα `--apply` χωρίς νέα προεπισκόπηση και διάγνωση. Διατηρήστε logs και backup.

## Logging και ασφάλεια
Χρησιμοποιούνται οι υπάρχοντες μηχανισμοί logging migrations και οι περιορισμοί του SQL Server. Καμία τροποποίηση σε ρόλους, tokens, διαπιστευτήρια και API. Πριν ενεργοποιηθεί εγγραφή τιμών θα προστεθούν δομημένα logs επιτυχιών/απορρίψεων, έλεγχοι δικαιωμάτων και ασφαλές CLI.

## Rollback / ανάκτηση
Το `Down` διαγράφει **όλους** τους δύο νέους πίνακες. Επομένως δεν θεωρείται ασφαλής διαδικασία διατήρησης δεδομένων. Μετά από καταχωρήσεις, η ανάκτηση πρέπει να σχεδιάζεται με επαληθευμένο backup και καταγραφή των αλλαγών. Πριν γίνει merge, η πιο ασφαλής επιστροφή είναι απλώς `git switch main` χωρίς εφαρμογή migration.

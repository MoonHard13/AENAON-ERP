## 1. Σκοπός και σύντομη περιγραφή

Αντιμετωπίζει δύο πρακτικά προβλήματα: αδυναμία αφαίρεσης μη άδειας κατηγορίας από μενού και ανάγκη επιλογής πολλών ειδών από τον ERP Catalog χωρίς αποθήκευση ένα-ένα.

Η αφαίρεση πλέον περιλαμβάνει ολόκληρο το υποδέντρο (υποκατηγορίες, υπο-υποκατηγορίες και συνδεδεμένα είδη), με ορατή ένδειξη πλήθους και υποχρεωτική checkbox επιβεβαίωσης. Η πολλαπλή προσθήκη επιλέγει έως **50 διαφορετικά ενεργά είδη ανά ενέργεια** και τα αποθηκεύει **όλα ή κανένα**, μέσα σε μία SQL transaction και με μία αύξηση της revision.

## 3. Προσθήκη πολλών ειδών από τον ERP Catalog

1. Μεταβείτε στο **Μενού εστίασης** και επιλέξτε **μόνο δοκιμαστικό μενού** για την αρχική αποδοχή.
2. Εισέλθετε στην κατηγορία ή μείνετε στο **Αρχικό μενού** για είδη ρίζας.
3. Επιλέξτε **Από ERP Catalog**. Στην περιοχή του καταλόγου εμφανίζονται πλαίσια **Επιλογή** για είδη που δεν έχουν ήδη προστεθεί στο τρέχον επίπεδο.
4. Επιλέξτε πολλαπλά είδη χειροκίνητα ή πατήστε **Επιλογή όλων** για τα διαθέσιμα αποτελέσματα της τρέχουσας αναζήτησης. Πατήστε **Καθαρισμός** αν θέλετε να μηδενιστεί η επιλογή.
5. Ελέγξτε την ένδειξη πλήθους και πατήστε **Προσθήκη επιλεγμένων**. Το κουμπί παραμένει ανενεργό όταν δεν έχει επιλεγεί κανένα είδος.
6. Περιμένετε να επιστρέψει η εφαρμογή στο μενού. Η νέα σειρά ειδών συνεχίζει μετά τα υπάρχοντα είδη του συγκεκριμένου επιπέδου.
7. Ανανεώστε τη σελίδα και επιβεβαιώστε αποθήκευση όλων των ειδών. Δεν αλλάζει καμία εγγραφή στο ERP Catalog.

**Όριο:** Η αναζήτηση επιστρέφει έως 50 είδη και η εντολή δέχεται έως 50 GUIDs. Η επιλογή δεν διατηρείται μεταξύ διαφορετικών αναζητήσεων. Μπορούν να εκτελεστούν διαδοχικές αποθηκεύσεις για περισσότερα είδη. Το μεμονωμένο κουμπί + παραμένει διαθέσιμο.

**Συμπεριφορά σφάλματος:** Αν εντοπιστεί ανενεργό/ξένο ERP είδος, διπλό είδος στο συγκεκριμένο επίπεδο, μη έγκυρη επιλογή ή σύγκρουση revision, **δεν αποθηκεύεται κανένα είδος της ομάδας**. Η επανάληψη με το ίδιο RequestId δεν προκαλεί διπλή εγγραφή.

## 4. Αφαίρεση κατηγορίας μαζί με περιεχόμενο

1. Βρείτε την επιθυμητή κατηγορία στο προσχέδιο και ανοίξτε το εικονίδιο **Ενέργειες** (γρανάζι).
2. Επιλέξτε **Αφαίρεση από μενού**.
3. Διαβάστε την επίδραση: πόσες **υποκατηγορίες όλων των επιπέδων** και πόσα **συνδεδεμένα είδη** πρόκειται να αφαιρεθούν από το μενού.
4. Επιλέξτε το υποχρεωτικό checkbox **Επιβεβαιώνω την αφαίρεση...**.
5. Πατήστε **Αφαίρεση κατηγορίας από το μενού**.
6. Η εφαρμογή απορρίπτει αφαίρεση με περιεχόμενο χωρίς ρητή επιβεβαίωση· επιβεβαιώνει ξανά tenant/menu/revision server-side.
7. Μετά την αποθήκευση, ανανεώστε: το επιλεγμένο κλαδί δεν εμφανίζεται, οι υπόλοιπες κατηγορίες αναριθμούνται, ο ERP Catalog και άλλα μενού διατηρούνται αμετάβλητα.

**Δεν υποστηρίζεται** επαναφορά του διαγραμμένου υποδέντρου με ένα κλικ. Αν χρειαστεί, η ανάκτηση απαιτεί νέα χειροκίνητη σύνθεση ή εγκεκριμένο restore απομονωμένων δεδομένων. Μην εκτελείτε αλλαγές SQL χωρίς χωριστή έγκριση.

## 5. Πεδία, προστασίες και κανόνες

| Πεδίο / μηχανισμός | Περιγραφή |
| --- | --- |
| `MenuDraftAction.AddItems` | Μαζική εντολή, μία transaction |
| `CatalogItemIds` | Λίστα 1–50 μοναδικών, μη κενών GUIDs |
| `RemoveContents` | Υποχρεωτική ρητή ένδειξη για αφαίρεση μη άδειου κλάδου |
| `TenantId` + `MenuId` | Server-side απομόνωση κάθε εγγραφής, όχι εμπιστοσύνη στο HTML |
| `CategoryId` | Προαιρετικό για είδη ρίζας, αναγκαίο για αφαίρεση κατηγορίας |
| `RequestId` | Idempotency για retry και διπλά clicks |
| `ExpectedRevision` | Αποτροπή αλλαγής πάνω σε παλιότερη εκδοχή του μενού |
| `__RequestVerificationToken` | CSRF/antiforgery προστασία HTTPS φόρμας |

Όλες οι ενέργειες χρησιμοποιούν το κοινό Application service για UI/CLI. Το backend ελέγχει ταυτότητα, δικαιώματα Owner, ενεργά είδη, μη ύπαρξη duplicate στο ίδιο επίπεδο, όρια θέσεων και πραγματική αναθεώρηση. Καταγράφεται structured log επιτυχίας/αποτυχίας χωρίς κωδικούς πρόσβασης.

## 6. Συντομεύσεις πληκτρολογίου

- **Tab / Shift+Tab:** μετακίνηση στα checkboxes, στις επιλογές και στα κουμπιά.
- **Space:** επιλογή/αποεπιλογή είδους ή ρητής επιβεβαίωσης αφαίρεσης.
- **Enter / Space:** ενεργοποίηση των κουμπιών «Επιλογή όλων», «Καθαρισμός» και υποβολής.
- **Ctrl+S / Cmd+S:** αποθήκευση όταν η εστίαση βρίσκεται στη φόρμα πολλαπλής επιλογής ή στην επιβεβαίωση αφαίρεσης. Η φόρμα παραμένει υπό έλεγχο CSRF, required fields και server-side validations.

## 7. CLI / CMD

Ο CLI μηχανισμός προσφέρει τις ίδιες ενέργειες, με επαλήθευση κωδικού διαδραστικά, Development database confirmation, dry-run και ασφαλή exit codes.

~~~powershell
# Προεπισκόπηση επιλεγμένων ειδών χωρίς SQL write
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-menus --username admin --tenant-id "TENANT_GUID" --confirm-database AenaonERP_Dev --action add-items --menu-id "MENU_GUID" --category-id "CATEGORY_GUID" --catalog-item-ids "PRODUCT_GUID_1,PRODUCT_GUID_2" --expected-revision 1 --dry-run

# Προεπισκόπηση αφαίρεσης ολόκληρου κλάδου, χωρίς SQL write
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-menus --username admin --tenant-id "TENANT_GUID" --confirm-database AenaonERP_Dev --action remove-category --menu-id "MENU_GUID" --category-id "CATEGORY_GUID" --expected-revision 1 --remove-contents --dry-run
~~~

Για είδη στην αρχική οθόνη παραλείπεται το `--category-id`. Η πραγματική καταχώριση απαιτεί `--apply` **μόνο μετά από χωριστή έγκριση της συγκεκριμένης δοκιμαστικής εγγραφής**. Ποτέ κωδικός χρήστη σε argument.

## 8. Έλεγχοι πριν/μετά, acceptance και troubleshooting

**Πριν:** σωστό Tenant/Menu/ρόλος, backup δοκιμαστικής βάσης, τρέχουσα revision, επιθυμητός κατάλογος ειδών και αριθμός επιλεγμένων. **Μετά:** ανανέωση σελίδας, επιβεβαίωση πλήθους/σειράς, μη αλλαγή στον ERP Catalog/άλλα μενού, μία μόνο αύξηση revision για ολόκληρο batch.

- [ ] Owner: πολλαπλή επιλογή 2–5 ειδών, αποθήκευση, refresh.
- [ ] Επιλογή όλων, καθαρισμός, χωρίς επιλογή και διαφορετική αναζήτηση.
- [ ] Duplicate/inactive/foreign GUID → απόρριψη όλων, καμία μερική εγγραφή.
- [ ] Ταυτόχρονη αλλαγή revision και retry RequestId.
- [ ] Member δεν βλέπει ελεγκτή διαχείρισης, POST απορρίπτεται.
- [ ] Αφαίρεση κατηγορίας με άμεσα είδη, παιδιά και εγγόνια, με ρητή επιβεβαίωση.
- [ ] Χωρίς επιβεβαίωση → απόρριψη, κανένα SQL write.
- [ ] Διατήρηση ειδών ρίζας/αδελφών κατηγοριών/ERP Catalog/άλλων μενού.
- [ ] Desktop, mobile 320/375/390/768/1366/1920, Light/Dark, zoom, keyboard, πραγματικά screenshots.
- [ ] CI Windows/Ubuntu + isolated SQL Server 2022 regression tests PASS πριν από αποδοχή.

**Troubleshooting:** Αν δεν φαίνεται η επιλογή, ελέγξτε ότι είστε Owner και ότι το είδος δεν υπάρχει ήδη στο συγκεκριμένο επίπεδο. Αν απορριφθεί batch, ανανεώστε και ελέγξτε ενεργά/διπλά είδη και revision· κανένα μερικό batch δεν πρέπει να έχει καταχωριστεί. Αν δεν φαίνεται η αφαίρεση, ανοίξτε το γρανάζι της συγκεκριμένης κατηγορίας και ελέγξτε την υποχρεωτική επιβεβαίωση. Στα κινητά χρησιμοποιήστε το προσαρμοσμένο responsive toolbar και τα native checkboxes.

## 9. Πότε χρησιμοποιείται / πότε δεν χρησιμοποιείται — best practices

Χρησιμοποιείται για σύνθεση Draft Menu, ασφαλή αφαίρεση μιας συγκεκριμένης κατηγορίας από το μενού και ομαδική σύνδεση ήδη διαθέσιμων ERP ειδών. Δεν χρησιμοποιείται για διαγραφή από τον ERP Catalog, μαζική επεξεργασία τιμών, δημοσίευση μενού, POS, παραγγελίες, αποθήκη, εκτύπωση ή φορολογική έκδοση.

Προτιμήστε πρώτα προσωρινό δοκιμαστικό μενού με μη παραγωγικά δεδομένα. Κατά την αφαίρεση διαβάστε τα πραγματικά πλήθη, μην ενεργείτε σε μη επιλεγμένο Tenant και μη παρακάμπτετε τη φόρμα μέσω χειροκίνητης SQL.

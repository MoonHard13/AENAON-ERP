# Aenaon ERP — Επιχειρήσεις και καταστήματα

## Σκοπός

Ορισμός των πρώτων επιχειρησιακών μοντέλων: μιας ανεξάρτητης επιχείρησης και των καταστημάτων της. Οι κανόνες τους συγκεντρώνονται στο `Aenaon.Domain`, ώστε αργότερα να χρησιμοποιούνται από τις υπηρεσίες εφαρμογής ανεξάρτητα από το περιβάλλον χρήσης.

## Τι περιλαμβάνει το δεύτερο βήμα

| Στοιχείο | Χρήση |
| --- | --- |
| `Tenant` | Επιχείρηση με δικό της αναγνωριστικό, όνομα και συλλογή καταστημάτων. |
| `Store` | Κατάστημα που ανήκει σε συγκεκριμένη επιχείρηση. |
| `DomainRuleException` | Σφάλμα επιχειρησιακού κανόνα με σταθερό κωδικό και μήνυμα στα Ελληνικά. |
| `Aenaon.Domain.Tests` | Έλεγχοι ορίων πεδίων, ιδιοκτησίας, διπλών κωδικών και ανεξάρτητων συλλογών. |

Τα νέα μοντέλα επαληθεύονται μέσω unit tests. Η καταχώρηση από φόρμες, η βάση δεδομένων και τα σχετικά API endpoints αποτελούν επόμενα βήματα.

## Ενημέρωση του τοπικού έργου

1. Σταμάτησε το API με `Ctrl+C` στο τερματικό όπου εκτελείται.
2. Από τον κεντρικό φάκελο `AENAON-ERP`, έλεγξε τις τοπικές αλλαγές:

```powershell
git status
```

3. Αν έχεις δικές σου αλλαγές, διατήρησέ τες σε commit ή ξεχωριστό branch πριν ενημερώσεις το έργο. Διαφορετικά εκτέλεσε:

```powershell
git pull --ff-only origin main
dotnet restore AenaonERP.slnx --locked-mode
dotnet test AenaonERP.slnx --configuration Release --no-restore
```

Η τελευταία εντολή κάνει build και εκτελεί τόσο τα νέα unit tests όσο και τα υπάρχοντα integration tests. Το πιστοποιητικό HTTPS που εμπιστεύτηκες στο πρώτο βήμα παραμένει το ίδιο.

## Πεδία

| Μοντέλο | Πεδίο | Επεξήγηση |
| --- | --- | --- |
| `Tenant` | `Id` | Αυτόματο αναγνωριστικό `Guid` της επιχείρησης. |
| `Tenant` | `Name` | Υποχρεωτικό όνομα, έως 160 χαρακτήρες. |
| `Tenant` | `Stores` | Συλλογή καταστημάτων διαθέσιμη για ανάγνωση. Η προσθήκη γίνεται με `AddStore`. |
| `Store` | `Id` | Αυτόματο αναγνωριστικό `Guid` του καταστήματος. |
| `Store` | `TenantId` | Αναγνωριστικό της επιχείρησης που κατέχει το κατάστημα. |
| `Store` | `Code` | Υποχρεωτικός κωδικός έως 30 χαρακτήρες: γράμματα, αριθμοί, παύλα ή κάτω παύλα. |
| `Store` | `Name` | Υποχρεωτικό όνομα έως 160 χαρακτήρες. |

Αφαιρούνται τα κενά από την αρχή και το τέλος των ονομάτων/κωδικών. Οι κωδικοί αποθηκεύονται με κεφαλαία. Οι χαρακτήρες ελέγχου, όπως αλλαγή γραμμής και tab, απορρίπτονται.

## Κανόνας μοναδικότητας

| Επιχείρηση | Κωδικός καταστήματος | Αποτέλεσμα |
| --- | --- | --- |
| Πρώτη επιχείρηση | `MAIN` | Επιτρέπεται. |
| Δεύτερη επιχείρηση | `MAIN` | Επιτρέπεται, καθώς είναι διαφορετικός ιδιοκτήτης. |
| Πρώτη επιχείρηση, δεύτερη καταχώρηση | `main` | Απορρίπτεται ως διπλός κωδικός. |

Η ίδια λογική ισχύει και όταν υπάρχουν κενά γύρω από τον κωδικό, όπως ` MAIN `. Η αποτυχημένη προσθήκη δεν μεταβάλλει τη συλλογή καταστημάτων.

## Παράδειγμα χρήσης των μοντέλων

```csharp
using Aenaon.Domain.Tenancy;

var tenant = Tenant.Create("Επιχείρηση Demo");
var store = tenant.AddStore("ath-01", "Κατάστημα Αθήνας");

Console.WriteLine(tenant.Name);
Console.WriteLine(store.Code);
Console.WriteLine(store.TenantId == tenant.Id);
```

Το παράδειγμα θα δώσει όνομα `Επιχείρηση Demo`, κωδικό `ATH-01` και `True` για τον έλεγχο ιδιοκτησίας. Αφορά κώδικα εφαρμογής που αναφέρεται στο Domain project.

## Κωδικοί σφαλμάτων

| Κωδικός | Αιτία / ενέργεια |
| --- | --- |
| `tenant.name.invalid` | Συμπλήρωσε όνομα επιχείρησης 1–160 χαρακτήρων χωρίς χαρακτήρες ελέγχου. |
| `store.tenant.required` | Το κατάστημα πρέπει να συνδεθεί με επιχείρηση μέσω της `AddStore`. |
| `store.code.invalid` | Έλεγξε μήκος και χαρακτήρες του κωδικού καταστήματος. |
| `store.name.invalid` | Συμπλήρωσε όνομα καταστήματος 1–160 χαρακτήρων χωρίς χαρακτήρες ελέγχου. |
| `store.code.duplicate` | Διάλεξε άλλο κωδικό για την ίδια επιχείρηση. |

## Πότε χρησιμοποιούνται οι κανόνες

Χρησιμοποιούνται κατά τη δημιουργία επιχειρήσεων και την προσθήκη καταστημάτων. Δεν ορίζουν φορολογική ταυτότητα, ΚΑΔ, σειρές παραστατικών, λογαριασμούς ή δικαιώματα χρηστών.

{% hint style="info" %}
Η ιδιοκτησία των αντικειμένων είναι το πρώτο δομικό βήμα. Η πραγματική απομόνωση επιχειρήσεων χρειάζεται επίσης έλεγχο εξουσιοδότησης στα αιτήματα, περιορισμό των SQL queries στην επιχείρηση του χρήστη και περιορισμούς στη βάση δεδομένων. Αυτά θα προστεθούν πριν χρησιμοποιηθούν πραγματικά επιχειρησιακά δεδομένα.
{% endhint %}

Όταν προστεθεί η αποθήκευση, η μοναδικότητα κωδικών πρέπει να προστατεύεται και στη βάση με περιορισμό στα `TenantId` και `Code`, ώστε να ισχύει και για ταυτόχρονες εγγραφές από διαφορετικές διεργασίες.

## Έλεγχοι από CLI

Μόνο τα unit tests του Domain:

```powershell
dotnet test tests/Aenaon.Domain.Tests --configuration Release --no-restore
```

Όλοι οι έλεγχοι:

```powershell
dotnet format AenaonERP.slnx --verify-no-changes --no-restore
dotnet build AenaonERP.slnx --configuration Release --no-restore
dotnet test AenaonERP.slnx --configuration Release --no-build --no-restore
```

Επανεκκίνηση του API:

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https
```

Το `https://localhost:7140/health` εξακολουθεί να επιστρέφει `Healthy`.

## Αντιμετώπιση προβλημάτων

| Πρόβλημα | Ενέργεια |
| --- | --- |
| Δεν εμφανίζεται το `Aenaon.Domain` | Επιβεβαίωσε ότι το `git pull` ολοκληρώθηκε και ότι βρίσκεσαι στη σωστή solution. |
| Σφάλμα κλειδωμένων εξαρτήσεων | Έλεγξε ότι κατέβηκαν και τα νέα `packages.lock.json`, χωρίς να παρακάμψεις τον έλεγχο. |
| `store.code.duplicate` με διαφορετικά πεζά/κεφαλαία | Οι κωδικοί συγκρίνονται χωρίς διάκριση πεζών/κεφαλαίων. Χρησιμοποίησε διαφορετικό κωδικό. |
| Αποτυγχάνει η άμεση προσθήκη στη `Stores` | Η συλλογή είναι μόνο για ανάγνωση. Χρησιμοποίησε `tenant.AddStore(...)`. |
| Το build αναφέρει κλειδωμένο αρχείο | Σταμάτησε την προηγούμενη εκτέλεση του API με `Ctrl+C` και επανάλαβε. |

## Έλεγχος ολοκλήρωσης

- [ ] Εμφανίζονται τα projects `Aenaon.Domain` και `Aenaon.Domain.Tests` στη solution.
- [ ] Το restore με `--locked-mode` ολοκληρώνεται.
- [ ] Το Release build και όλα τα tests περνούν.
- [ ] Το `/health` λειτουργεί όπως στο πρώτο βήμα.
- [ ] Είναι σαφές ότι οι επιχειρήσεις/τα καταστήματα αυτού του σταδίου δεν αποθηκεύονται ακόμη σε βάση.

Οι κλάσεις Domain διατηρούν τους κανόνες τους χωρίς εξάρτηση από HTTP, logging, βάση δεδομένων ή επιπλέον NuGet packages. Τα logs και η ταυτότητα του χρήστη θα συνδέονται με τις επιχειρησιακές ενέργειες στο επίπεδο εφαρμογής.

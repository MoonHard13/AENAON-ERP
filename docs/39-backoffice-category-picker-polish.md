# AENAON ERP — Βήμα 9.4C.2: Back Office UI Polish & Category Picker

## 1. Σκοπός

Το 9.4C.2 ολοκληρώνει την οπτική και λειτουργική συνέπεια του **Back Office καταλόγου**. Διορθώνει την ελληνική γραμματική των ενεργειών, εισάγει **κοινό αναζητήσιμο Category Picker** για προϊόντα, υπηρεσίες και γονικές κατηγορίες, βελτιώνει την προσβασιμότητα και διατηρεί επιχείρηση/κατάστημα όταν δημιουργούμε κατηγορία μέσα από ημιτελή καταχώρηση.

{% hint style="info" %}
Πρόκειται για αλλαγές **UI / API validation**. **Δεν υπάρχει νέα EF migration**, αλλαγή φορολογικών πεδίων ή αυτόματη εγγραφή στον SQL Server. Οι 6 υπάρχουσες migrations παραμένουν ως έχουν.
{% endhint %}

## 2. Απαιτήσεις και προέλεγχος

- Windows με .NET 10 SDK που ορίζει το `global.json`, Visual Studio/VS Code ή PowerShell.
- SQL Server 2022, Development DB `AenaonERP_Dev`, 6 applied και 0 pending migrations.
- Το AENAON API σε HTTPS Development με έγκυρο session cookie.
- Δικαίωμα **Owner/Manage** στην επιλεγμένη επιχείρηση.
- PR 9.4C.1/9.4C να έχει προηγηθεί. Backup Development βάσης πριν από δοκιμές πραγματικών καταχωρήσεων.

**Προέλεγχος:** Κλείστε τυχόν προηγούμενο instance της εφαρμογής με `Ctrl+C`, ώστε οι νέες αλλαγές Razor/C# να φορτωθούν στην επανεκκίνηση.

| Ενότητα | Σωστό κείμενο δημιουργίας |

## 4. Νέος Category Picker

### 4.1 Χρήση σε προϊόν / υπηρεσία

1. Επιλέξτε **Κατάλογος → Προϊόντα → Νέο προϊόν** ή **Υπηρεσίες → Νέα υπηρεσία**.
2. Εστιάστε στο πεδίο **Κατηγορία**. Θα εμφανιστεί το ενιαίο, επαγγελματικό dropdown.
3. Πληκτρολογήστε μέρος του κωδικού ή της περιγραφής.
4. Η εφαρμογή αναζητά ενεργές κατηγορίες της δικής σας επιχείρησης μέσω του server, με όριο **30 αποτελεσμάτων** ανά αναζήτηση.
5. Μετακινηθείτε με `↑` / `↓` και πατήστε `Enter` ή επιλέξτε με ποντίκι.
6. Η επιλογή εμφανίζει τη διαδρομή, π.χ. `ΠΟΤΑ / ΑΝΑΨΥΚΤΙΚΑ` και τον κωδικό.
7. Αποθηκεύστε την καταχώρηση. Το backend **ελέγχει ξανά** ότι η κατηγορία είναι ενεργή και ανήκει στην επιχείρηση.

Δεν χρειάζεται δεύτερο ξεχωριστό πεδίο αναζήτησης και native dropdown. Ο native επιλογέας υπάρχει **μόνο ως fallback** όταν δεν εκτελείται JavaScript.

### 4.2 Χρήση στη γονική κατηγορία

1. Επιλέξτε **Κατάλογος → Κατηγορίες → Νέα κατηγορία** ή **Επεξεργασία**.
2. Στο πεδίο **Γονική κατηγορία** επιλέξτε υπάρχουσα κατηγορία.
3. Εναλλακτικά, επιλέξτε **«Καμία — κύρια κατηγορία»** για εγγραφή ρίζας.
4. Η εφαρμογή αποκλείει τον εαυτό της από τις προτεινόμενες κατηγορίες. Το backend απαγορεύει και κυκλικές σχέσεις ή σχέσεις με κατηγορίες διαφορετικού Tenant.

### 4.3 Νέα κατηγορία από ανοιχτή φόρμα προϊόντος

1. Ενώ συμπληρώνετε προϊόν ή υπηρεσία, ανοίξτε το Category Picker.
2. Στο κάτω μέρος επιλέξτε **«Δεν υπάρχει η κατηγορία; Δημιουργήστε νέα»**.
3. Η εφαρμογή κρατά προσωρινά κωδικό, περιγραφή, επιλογή παρακολούθησης αποθέματος, επιχείρηση και κατάστημα.
4. Δημιουργήστε τη νέα κατηγορία.
5. Μετά την επιτυχή αποθήκευση, επιστρέφετε στο αρχικό προϊόν/υπηρεσία με τα προηγούμενα δεδομένα και τη νέα κατηγορία επιλεγμένη.
6. Το **«Πίσω στην καταχώρηση»** επιστρέφει χωρίς δημιουργία κατηγορίας.

{% hint style="warning" %}
Τα πρόχειρα δεδομένα αποθηκεύονται **προσωρινά στη μνήμη**, με περιορισμένη διάρκεια και σύνδεση στον ίδιο χρήστη/Tenant. Απώλεια session ή επανεκκίνηση του API μπορεί να ακυρώσει την προσωρινή επαναφορά. Η δημιουργία κατηγορίας δεν αποθηκεύει αυτόματα και το προϊόν/υπηρεσία.
{% endhint %}

## 5. Πληκτρολόγιο και προσβασιμότητα

| Συντόμευση | Συμπεριφορά |
| --- | --- |
| `Tab`, `Shift+Tab` | Μετακίνηση μεταξύ πεδίων |
| `↑` / `↓` μέσα στο Category Picker | Αλλαγή επισημασμένου αποτελέσματος |
| `Enter` μέσα στο Category Picker | Επιλογή αποτελέσματος, **όχι καταχώρηση φόρμας** |
| `Escape` μέσα στο Picker | Κλείσιμο αποτελεσμάτων και επαναφορά επιλεγμένης τιμής |
| `Alt+K` | Γρήγορη δημιουργία κατηγορίας από προϊόν/υπηρεσία |
| `Alt+N` | Νέα εγγραφή από τη λίστα |
| `Alt+C` | Κατάλογος |
| `Alt+D` | Επισκόπηση |
| `Alt+Enter` | Αποθήκευση editor όπου είναι διαθέσιμο |
| `Alt+T` | Εναλλαγή θέματος |

Το control χρησιμοποιεί WAI-ARIA `combobox` / `listbox`, `aria-expanded`, `aria-controls`, `aria-activedescendant` και `role=status`. Ο focus indicator παραμένει ορατός για χρήση με πληκτρολόγιο. Οι επιλογές εισάγονται με ασφαλείς DOM text APIs (όχι `innerHTML`).

Εφόσον κάποιες συντομεύσεις `Alt` ανήκουν στον browser/λειτουργικό, υπάρχουν πάντα ορατά κουμπιά εναλλακτικής πλοήγησης.

## 6. Αναζήτηση και ανθεκτικότητα

- Το API `GET /ui/catalog/categories` είναι HTTPS, απαιτεί session και δικαίωμα **Manage**.
- Υποστηρίζει αναζήτηση prefix σε κωδικό/περιγραφή και επιστρέφει περιορισμένο αριθμό αποτελεσμάτων.
- Η JavaScript χρησιμοποιεί `AbortController` και διαδοχικό `sequence` για να αποτρέψει παλιότερες απαντήσεις δικτύου από το να αντικαταστήσουν νεότερες.
- Σε αποτυχία δικτύου εμφανίζεται φιλικό μήνυμα, χωρίς να εκτίθενται εξαιρέσεις SQL στον χρήστη.
- Η τελική αποθήκευση εξακολουθεί να εφαρμόζει server-side δικαιώματα, CSRF, validation, tenant isolation και idempotency.

## 7. Light / Dark και responsive design

Το dropdown ακολουθεί τα ήδη υπάρχοντα CSS variables (`--surface-raised`, `--border`, `--text`, `--positive`) σε όλες τις οθόνες. Η επιλεγμένη τιμή, τα αποτελέσματα, τα μηνύματα κατάστασης και η ενέργεια δημιουργίας χρησιμοποιούν την ίδια οπτική γλώσσα.

Ο editor παραμένει full-width **μέσα στην περιοχή περιεχομένου**, ενώ το sidebar διατηρείται. Στα κινητά τα πεδία μετατρέπονται σε μία στήλη, το dropdown περιορίζει το ύψος του και υποστηρίζει κύλιση.

Συνιστώ οπτικό έλεγχο σε zoom 100%, 150% και 200% και μεγέθη browser desktop/mobile.

## 8. Γιατί το Ctrl+F5 δεν ήταν η κατάλληλη οδηγία

Στον **Google Chrome για Windows**:

- `F5` ή `Ctrl+R`: απλή ανανέωση.
- `Shift+F5` ή **`Ctrl+Shift+R`**: ανανέωση αγνοώντας προσωρινά τα cached resources.
- `Ctrl+F5`: ενδέχεται να μεταφέρει την εστίαση στη γραμμή διευθύνσεων, σύμφωνα με την τρέχουσα τεκμηρίωση Chrome.

Για CSS/JavaScript, το AENAON χρησιμοποιεί επιπλέον **SHA-256 asset fingerprints** στα URL των αρχείων, συνεπώς η νέα έκδοση ζητά αυτόματα καινούριο resource.

{% hint style="info" %}
Η ανανέωση του browser **δεν κάνει build του C# ή των Razor αρχείων**. Μετά από αλλαγή branch, τερματίστε το παλιό instance του API και εκτελέστε πάλι `dotnet run`.
{% endhint %}

## 9. Build και εγκατάσταση δοκιμής

Από PowerShell:

```powershell
cd "$env:USERPROFILE\Desktop\AENAON-ERP"
git status --short
git fetch origin
git switch feature/9-4c-2-backoffice-category-picker-polish
git pull --ff-only origin feature/9-4c-2-backoffice-category-picker-polish
dotnet restore AenaonERP.slnx --locked-mode
dotnet format AenaonERP.slnx --verify-no-changes --no-restore
dotnet build AenaonERP.slnx -c Release --no-restore
dotnet test AenaonERP.slnx -c Release --no-build --no-restore --filter "TestCategory!=SqlServer"
dotnet run --project src/Aenaon.Api --launch-profile https
```

Ανοίξτε `https://localhost:7140/catalog`. Εφόσον το περιβάλλον διαθέτει πλέον 6 εφαρμοσμένες migrations, το UI δεν χρειάζεται καμία νέα εντολή `--migrate-database --apply`.

## 11. Troubleshooting

| Σύμπτωμα | Αντιμετώπιση |
| --- | --- |
| Εμφανίζεται ακόμα το παλιό dropdown | Κλείστε το παλιό API, εκκινήστε το νέο branch και κάντε `Ctrl+Shift+R`. Ελέγξτε αν φορτώνει το `aenaon-category-picker.js`. |
| Δεν φορτώνουν κατηγορίες | Ελέγξτε το HTTPS, το session cookie, το δικαίωμα Owner και τα logs του API. |
| Η νέα κατηγορία δεν επιλέγεται | Ελέγξτε το redirect σε `/catalog/manage` και το προσωρινό draft. |
| Δύο πεδία κατηγορίας | Πιθανή αποτυχία JavaScript initialization. Ο native select είναι fallback, όχι δεύτερο ενεργό πεδίο μετά την αρχικοποίηση. |
| Απορρίπτεται η αποθήκευση | Επιβεβαιώστε ότι επιλέχθηκε έγκυρη κατηγορία, ότι δεν είναι ανενεργή και ότι ανήκει στο σωστό Tenant. |
| Δεν εμφανίζεται «Νέα κατηγορία» | Ελέγξτε τη σύνδεση και τα δικαιώματα Owner/Manage. |

## 12. Ασφάλεια, backup και rollback

Οι αλλαγές δεν τροποποιούν schema, οικονομικά δεδομένα, τιμές ή φορολογικούς χαρακτηρισμούς. Δεν απαιτείται νέο SQL backup αποκλειστικά για ανανέωση στατικών αρχείων, αλλά για δοκιμές πραγματικών εγγραφών απαιτείται το ισχύον backup της Development βάσης.

Για rollback, επαναφέρετε με `git revert` το merge ή κάντε switch στο προηγούμενο branch και επανεκκινήστε. Επειδή δεν υπάρχει νέα migration, δεν χρειάζεται `Down`. Εγγραφές που δημιουργήθηκαν κατά τις δοκιμές **δεν αναιρούνται** από αλλαγή κώδικα.

Δεν αλλάζουν οι κανόνες myDATA/IMPACT, δεν εκδίδονται παραστατικά και δεν μεταβάλλεται το fiscal gate.

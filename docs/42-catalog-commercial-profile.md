# AENAON ERP — 9.5A: Μονάδες μέτρησης και λογιστικοί τύποι ειδών

## 1. Σκοπός

Το βήμα **9.5A** επεκτείνει την υπάρχουσα καρτέλα **Προϊόντος / Υπηρεσίας** με δύο ανεξάρτητα εμπορικά πεδία: **Μονάδα μέτρησης** και **Λογιστικός τύπος είδους**. Τα νέα πεδία εμφανίζονται και στη λίστα του καταλόγου, όπου υποστηρίζουν ταξινόμηση πριν από τη σελιδοποίηση.

{% hint style="info" %}
Ο λογιστικός τύπος είναι **πεδίο εμπορικής ταξινόμησης**, όχι από μόνος του λογαριασμός Γενικής Λογιστικής, χαρακτηρισμός Ε3/myDATA ή ΦΠΑ. Δεν υπάρχει αυτόματη αποστολή στην ΑΑΔΕ ή στον IMPACT και δεν εκδίδονται παραστατικά.
{% endhint %}

## 2. Προϋποθέσεις

- .NET SDK κατάλληλο για το `global.json` (τουλάχιστον το εγκατεστημένο στο Development `10.0.404`).
- SQL Server 2022 και **Development** βάση `AenaonERP_Dev`.
- Εγκατεστημένες 6 προηγούμενες migrations, 0 εκκρεμείς πριν από την αναβάθμιση.
- Ενεργό HTTPS, έγκυρη σύνδεση και δικαίωμα Owner/Manage στον Tenant.
- Backup και διαθέσιμος χώρος για ασφαλή επαναφορά πριν από εφαρμογή migration.

## 3. Διαθέσιμες μονάδες

| Επιλογή | Ενδεικτικό πεδίο |
| --- | --- |
| Τεμάχιο (τεμ.) | Συσκευασμένα εμπορεύματα |
| Κιλό (kg) | Προϊόντα και πρώτες ύλες |
| Γραμμάριο (g) | Μικροποσότητες |
| Λίτρο (L) | Χύμα υγρά |
| Χιλιοστόλιτρο (ml) | Ροφήματα ή δοσομετρήσεις |
| Μερίδα | Είδη παρασκευής εστίασης |
| Ώρα | Υπηρεσίες ανά ώρα ή ωριαία προϊόντα |
| Υπηρεσία | Παροχή υπηρεσίας |

Οι μονάδες είναι προσωρινά **ελεγχόμενος σταθερός κατάλογος** (κωδικοί enum 1–8). Δεν υλοποιείται ακόμη δημιουργία ελεύθερων μονάδων, πολλαπλές μονάδες ανά προϊόν, αυτόματη μετατροπή μονάδων ή τιμολόγηση βάσει ποσότητας· αυτά απαιτούν ξεχωριστό σχεδιασμό πριν από POS/αποθήκη.

## 4. Διαθέσιμοι λογιστικοί τύποι

| Επιλογή | Περιγραφή |
| --- | --- |
| Εμπόρευμα | Αγορές και μεταπώληση |
| Προϊόν παραγωγής | Είδη που παράγονται ή παρασκευάζονται |
| Πρώτη ύλη | Υλικά που χρησιμοποιούνται σε παραγωγή |
| Αναλώσιμο | Λειτουργικά υλικά και αναλώσιμα |
| Υπηρεσία | Παροχή υπηρεσίας |
| Πάγιο | Εξοπλισμός / λοιπά πάγια |

Ο **τεχνικός τύπος** του καταλόγου (`Product` ή `Service`) δεν αλλάζει μετά τη δημιουργία. Ο λογιστικός τύπος είναι διαφορετική ιδιότητα, η οποία μπορεί να ενημερωθεί με κατάλληλο δικαίωμα και έλεγχο εγκυρότητας.

### Περιορισμοί και προεπιλογές

- Προϊόν: προεπιλογή **Τεμάχιο / Εμπόρευμα**· δυνατότητα των υπολοίπων μονάδων εκτός «Υπηρεσία» και λογιστικών τύπων εκτός «Υπηρεσία».
- Υπηρεσία: προεπιλογή **Υπηρεσία / Υπηρεσία**· επιτρέπεται μονάδα **Ώρα** ή **Υπηρεσία**, αλλά όχι παρακολούθηση αποθέματος.
- Παλιά προϊόντα: διατηρούν κωδικό, περιγραφή, κατηγορία και κατάσταση και αποκτούν την ασφαλή προεπιλογή.
- Παλιές υπηρεσίες: μεταφέρονται αυτόματα σε **Υπηρεσία / Υπηρεσία** κατά την έβδομη migration. Δεν επηρεάζεται η καταχώριση.
- Η βάση προστατεύει επίσης τους κανόνες με SQL CHECK constraints· άκυροι συνδυασμοί απορρίπτονται και αν παρακαμφθεί το UI.

{% hint style="warning" %}
Οι προκαθορισμένοι λογιστικοί τύποι χρειάζονται μελλοντική αντιστοίχιση με την πολιτική λογιστικής κάθε επιχείρησης, το λογιστικό σχέδιο και την πραγματική συναλλαγή. **Μην τους χρησιμοποιείτε ως αυτοματοποιημένους φορολογικούς χαρακτηρισμούς** πριν από έλεγχο myDATA και IMPACT.
{% endhint %}

## 5. Δημιουργία / επεξεργασία προϊόντος

1. Συνδεθείτε με δικαίωμα Owner/Manage και ανοίξτε **Κατάλογος → Προϊόντα → Νέο προϊόν**.
2. Συμπληρώστε κωδικό (χειροκίνητο ή αυτόματο), περιγραφή και κατηγορία.
3. Στην ενότητα **Εμπορικά και λογιστικά στοιχεία**, επιλέξτε **Μονάδα μέτρησης**.
4. Επιλέξτε **Λογιστικό τύπο**, π.χ. «Πρώτη ύλη» για το αλεύρι.
5. Επιλέξτε «Παρακολούθηση αποθέματος» μόνο όταν το είδος πρέπει να παρακολουθείται στο μέλλον.
6. Πατήστε **Δημιουργία** ή **Αποθήκευση και νέο**. Το backend ελέγχει ξανά την κατηγορία, την πρόσβαση και τους νέους κανόνες.
7. Ανοίξτε τη λίστα: οι νέες στήλες **Μονάδα** και **Λογιστικός τύπος** εμφανίζουν τις αποθηκευμένες τιμές και έχουν δικό τους sorting.
8. Στην **Επεξεργασία** μπορείτε να μεταβάλετε τις επιλογές χωρίς να αλλάξετε τον κωδικό ή τον τεχνικό τύπο.

Η επιλογή **«Δεν βρίσκετε την κατηγορία; Δημιουργήστε νέα»** διατηρεί προσωρινά τον κωδικό, την περιγραφή, το κατάστημα και **τα δύο νέα εμπορικά πεδία**. Μετά τη δημιουργία νέας κατηγορίας επιστρέφετε στο αρχικό είδος.

## 6. Δημιουργία / επεξεργασία υπηρεσίας

Στην καρτέλα **Νέα υπηρεσία** επιλέξτε μονάδα «Υπηρεσία» ή «Ώρα». Ο λογιστικός τύπος «Υπηρεσία» είναι ο μόνος διαθέσιμος για τον τεχνικό τύπο Service. Δεν υπάρχει παρακολούθηση αποθέματος.

## 7. CLI / CMD

Η εμπορική μεταβολή υποστηρίζεται από την υπάρχουσα CLI εντολή `--manage-catalog` χρησιμοποιώντας την **ίδια** `CatalogWriteService` και τον έλεγχο δικαιωμάτων.

**Dry-run προϊόντος:**

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-catalog --username admin --tenant-id "TENANT_GUID" --confirm-database AenaonERP_Dev --view products --action create --auto-code --name "Αλεύρι" --category-id "CATEGORY_GUID" --unit Kilogram --accounting-type RawMaterial --dry-run
```

Για πραγματική αποθήκευση αντικαταστήστε `--dry-run` με `--apply`, μόνο αφού ελέγξετε επιχείρηση/βάση/δικαιώματα. Θα ζητηθεί διαδραστικά ο κωδικός λογαριασμού.

**Διαθέσιμες συμβολικές τιμές CLI:**

- `--unit`: `Piece`, `Kilogram`, `Gram`, `Liter`, `Milliliter`, `Portion`, `Hour`, `Service`.
- `--accounting-type`: `Merchandise`, `FinishedProduct`, `RawMaterial`, `Consumable`, `Service`, `FixedAsset`.

Σε προϋπάρχουσες αυτοματοποιήσεις που δεν στέλνουν νέα πεδία, η δημιουργία διατηρεί τις προεπιλογές και η ενημέρωση **δεν αντικαθιστά** τις ήδη αποθηκευμένες επιλογές. Μη έγκυρες τιμές επιστρέφουν exit code 2 πριν από credential verification.

## 8. Έβδομη migration — προεπισκόπηση, backup, επιβεβαίωση

Η νέα migration **`20261113100000_CatalogCommercialProfile`** προσθέτει δύο μη-null `int` στήλες στον `dbo.CatalogItems`, προεπιλεγμένες τιμές και SQL constraints. Δεν δημιουργούνται νέοι πίνακες, δεν αλλάζουν τιμές, ΦΠΑ ή φορολογικές αντιστοιχίσεις.

**Βήμα 1 — Προεπισκόπηση χωρίς μεταβολές:**

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --dry-run
```

Αναμένονται **6 εφαρμοσμένες και 1 εκκρεμής migration**.

**Βήμα 2 — Backup στο SSMS:**

```sql
BACKUP DATABASE [AenaonERP_Dev]
TO DISK = N'C:\SQLBackups\AenaonERP_Dev_Pre_9_5A.bak'
WITH COPY_ONLY, INIT, CHECKSUM, STATS = 10;

RESTORE VERIFYONLY
FROM DISK = N'C:\SQLBackups\AenaonERP_Dev_Pre_9_5A.bak'
WITH CHECKSUM;
```

Ο φάκελος πρέπει να υπάρχει **στο μηχάνημα SQL Server** και ο λογαριασμός της υπηρεσίας SQL να έχει δικαιώματα εγγραφής. Το `VERIFYONLY` δεν αντικαθιστά δοκιμαστική επαναφορά.

**Βήμα 3 — Εφαρμογή μόνο μετά από έγκριση/backup:**

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --apply --confirm-database AenaonERP_Dev
```

**Βήμα 4 — Επαλήθευση:**

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --dry-run
```

Αναμένονται **7 εφαρμοσμένες και 0 εκκρεμείς**. Για επιβεβαίωση, ανοίξτε υπάρχον προϊόν και υπηρεσία και ελέγξτε την προεπιλογή χωρίς νέα καταχώριση.

{% hint style="danger" %}
Μην εφαρμόζετε τη migration σε παραγωγική βάση. Η επαναφορά του παλιού κώδικα **μετά** τη migration δεν καταργεί τις νέες στήλες. Πραγματικό rollback schema θα διέγραφε τις δύο εμπορικές τιμές, επομένως απαιτεί σχεδιασμό και backup.
{% endhint %}

## 9. Tests / ποιότητα

Το PR περιλαμβάνει unit tests για ασφαλείς προεπιλογές, συμβατότητα Product/Service, απαγόρευση άκυρων συνδυασμών, CLI parsing, HTTP endpoint validation, SQL constraints, ανάγνωση/sorting και **πραγματική αναβάθμιση από την έκτη στην έβδομη migration** με προϋπάρχουσες εγγραφές, σε απομονωμένο SQL Server CI.

```powershell
dotnet restore AenaonERP.slnx --locked-mode
dotnet format AenaonERP.slnx --verify-no-changes --no-restore
dotnet build AenaonERP.slnx --configuration Release --no-restore
dotnet test AenaonERP.slnx --configuration Release --no-build --no-restore --filter "TestCategory!=SqlServer"
```

Μην ερμηνεύετε τα πράσινα automated tests ως έγκριση φορολογικών χαρακτηρισμών ή εγγύηση οπτικής ποιότητας στο πραγματικό Chrome.

## 11. Troubleshooting

| Σύμπτωμα | Ενέργεια |
| --- | --- |
| Δεν υπάρχουν οι στήλες στη SQL | Τρέξτε **μόνο** dry-run και επιβεβαιώστε ότι η migration εκκρεμεί. |
| HTTP 400 / άκυρη μονάδα | Ελέγξτε ότι το HTML POST στέλνει ορισμένη τιμή 1–8, μία φορά. |
| Απορρίπτεται προϊόν/υπηρεσία | Ελέγξτε το συμβατό ζεύγος Unit/Accounting, τα SQL constraints και τα structured logs. |
| Το GUI δείχνει παλιά πεδία | Ελέγξτε το ενεργό Git branch, επανεκκινήστε το .NET API και κάντε `Ctrl+Shift+R`. |
| Αποτυχία migration | Μην κάνετε επαναλαμβανόμενες αλλαγές schema. Διατηρήστε logs, backup και error πριν από οποιαδήποτε επαναφορά. |
| Το CLI δεν αποδέχεται επιλογή | Χρησιμοποιήστε τα συμβολικά enum names της ενότητας 7, όχι αυθαίρετα ελληνικά strings. |

## 12. Ασφάλεια και επόμενα βήματα

Όλες οι εγγραφές περνούν από `CatalogWriteService`, Owner/Manage, tenant-scoped SQL transaction, anti-CSRF στο GUI και structured logging. Δεν γράφονται credentials στα logs. Οι επιλογές μονάδων και τύπων δεν μπορούν να υπερβούν τη whitelist.

**9.5B:** σχεδιασμός πολλών τιμοκαταλόγων ανά είδος/υπηρεσία, ανεξάρτητων τιμών ανά κατάστημα και χρονική περίοδο. **9.5C:** φορολογικές αντιστοιχίσεις με ρητή επαλήθευση AAΔΕ myDATA/IMPACT. Καμία φορολογική ενεργοποίηση στο 9.5A.

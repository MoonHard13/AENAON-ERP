# Aenaon ERP — Βήμα 9.4C: Διαχείριση καταλόγου

## 1. Σκοπός

Το 9.4C μετατρέπει την προηγούμενη **μόνο-ανάγνωσης** οθόνη καταλόγου σε περιβάλλον επιτρεπόμενης **διαχείρισης από Owner**. Περιλαμβάνει κατηγορίες, προϊόντα και υπηρεσίες, χρησιμοποιώντας κοινή υπηρεσία `CatalogWriteService` για Blazor Back Office και CLI. Αποθηκεύει μόνο μη φορολογικά πεδία.

{% hint style="warning" %}
Το Back Office παραμένει **Development-only** και ο SQL Server `AenaonERP_Dev` είναι περιβάλλον ανάπτυξης. **Δεν** έχουν εγκριθεί φορολογικές ταξινομήσεις myDATA/IMPACT. Δεν προστίθενται τιμές, ΦΠΑ, εκδόσεις ΑΠΥ/ΤΠΥ, κινήσεις αποθήκης ή myDATA διαβιβάσεις.
{% endhint %}

## 2. Προϋποθέσεις

- .NET 10 σταθερό SDK και το `global.json` του repository.
- SQL Server 2022 με σωστά εφαρμοσμένες τις **ήδη υπάρχουσες πέντε migrations** στην `AenaonERP_Dev`.
- Έγκυρη HTTPS σύνδεση με secure session cookie.
- Χρήστης με **Owner/Manage** στον αντίστοιχο Tenant. Οι Members συνεχίζουν να έχουν μόνο **Read**.
- Ολοκληρωμένο 9.4B.2 και ενημερωμένο `main` πριν το feature.

## 3. Βήμα προς βήμα — Back Office

### 3.1 Κατηγορία

1. Συνδεθείτε στο `/login` με λογαριασμό **Owner**.
2. Μεταβείτε στο `/catalog?view=categories` ή επιλέξτε «Κατηγορίες».
3. Επιλέξτε **Νέα κατηγορία**.
4. Συμπληρώστε **Κωδικός** (μέχρι 30 χαρακτήρες: γράμματα, αριθμοί, `-`, `_`) και **Περιγραφή** (μέχρι 160 χαρακτήρες).
5. Επιλέξτε **Δημιουργία**. Η εφαρμογή ελέγχει τον κωδικό και στη SQL uniqueness constraint.
6. Για αλλαγές επιλέξτε **Επεξεργασία** δίπλα στη σχετική εγγραφή.
7. Η **Απενεργοποίηση** ζητά επιβεβαίωση και **δεν διαγράφει** την κατηγορία ούτε μεταβάλλει αυτόματα τα είδη της.

{% hint style="info" %}
Δημιουργήστε πρώτα μία ενεργή κατηγορία. Το σύστημα δεν επιτρέπει νέα προϊόντα/υπηρεσίες χωρίς ενεργή κατηγορία της ίδιας επιχείρησης.
{% endhint %}

### 3.2 Προϊόν

1. Μεταβείτε στην καρτέλα **Προϊόντα**.
2. Επιλέξτε **Νέο προϊόν**.
3. Συμπληρώστε **Κωδικός** (1–40), **Περιγραφή** (1–200), και **Κατηγορία**.
4. Ενεργοποιήστε την επιλογή **Παρακολούθηση αποθέματος** μόνο αν το προϊόν θα υποστηρίζει μελλοντικά λειτουργίες αποθήκης.
5. Επιλέξτε **Δημιουργία**.
6. Από την ενέργεια **Επεξεργασία** μπορείτε να αλλάξετε κωδικό, περιγραφή, κατηγορία ή την ένδειξη παρακολούθησης, όχι τον τύπο του είδους.
7. Για απενεργοποίηση/ενεργοποίηση απαιτείται επιβεβαίωση. Δεν γίνεται φυσική διαγραφή.

Η επιλογή `TracksStock` είναι **μόνο χαρακτηριστικό προϊόντος**. Δεν υπολογίζει υπόλοιπα, δεν καταχωρεί κίνηση και δεν ενημερώνει διαθεσιμότητα.

### 3.3 Υπηρεσία

1. Μεταβείτε στις **Υπηρεσίες** και επιλέξτε **Νέα υπηρεσία**.
2. Συμπληρώστε κωδικό, περιγραφή και ενεργή κατηγορία.
3. Δεν εμφανίζεται επιλογή αποθέματος. Οι υπηρεσίες **δεν** παρακολουθούν απόθεμα.
4. Χρησιμοποιήστε την επεξεργασία ή την αλλαγή ενεργής κατάστασης όπως στο προϊόν.

Ο τύπος `Product` ή `Service` **δεν αλλάζει** με edit. Αν απαιτηθεί αλλαγή, χρειάζεται νέα εγγραφή και απενεργοποίηση της προηγούμενης.

## 4. Πεδία, περιορισμοί και συμπεριφορά

| Πεδίο | Κατηγορία | Προϊόν | Υπηρεσία |
| --- | --- | --- | --- |
| Κωδικός | Υποχρεωτικός, max 30 | Υποχρεωτικός, max 40 | Υποχρεωτικός, max 40 |
| Περιγραφή | Max 160 | Max 200 | Max 200 |
| Κατηγορία | — | Υποχρεωτική, ενεργή | Υποχρεωτική, ενεργή |
| Παρακολούθηση αποθέματος | — | Ναι/Όχι | Απαγορεύεται |
| Ενεργό/Ανενεργό | Ναι | Ναι | Ναι |
| Τιμή/ΦΠΑ/myDATA | Δεν υλοποιείται | Δεν υλοποιείται | Δεν υλοποιείται |

Οι κωδικοί είναι **μοναδικοί ανά Tenant** σε επίπεδο κατηγοριών και — σε ξεχωριστό κοινό χώρο κωδικών — μεταξύ προϊόντων και υπηρεσιών. Ο έλεγχος επιβάλλεται και από τους SQL unique indexes με Greek_CI_AS collation.

Η λίστα επιλογής κατηγορίας περιορίζεται στις **300 πρώτες** εγγραφές· αν υπάρχουν περισσότερες, εμφανίζεται προειδοποίηση. Πρόκειται για περιορισμό της πρώτης έκδοσης του editor. Οι συνήθεις λίστες ανάγνωσης εξακολουθούν να χρησιμοποιούν server-side pagination.

## 5. Εξουσιοδότηση και προστασία

1. Η πρόσβαση γίνεται μέσω **HTTPS session cookie**, όχι ανεξέλεγκτου `userId` της φόρμας.
2. Ο server ελέγχει `TenantPermission.Manage` πριν από οποιαδήποτε ανάγνωση edit details ή SQL write.
3. Όλα τα queries χρησιμοποιούν υποχρεωτικό tenant-scoped predicate. Η κατηγορία ελέγχεται ότι ανήκει στον ίδιο Tenant και είναι ενεργή για νέες εγγραφές/μετακινήσεις.
4. Η καταχώρηση πραγματοποιείται μόνο με **POST + Anti-CSRF token** και όριο μεγέθους αίτησης 8192 bytes.
5. Η επιστροφή γίνεται με Redirect/GET· οι διπλοί κωδικοί δίνουν φιλικό μήνυμα.
6. Δεν υπάρχουν φυσικές διαγραφές, HTML injection ή ανεξέλεγκτο SQL. Οι κανονικές EF Core μέθοδοι χρησιμοποιούν παραμετροποιημένα SQL.
7. Τα logs καταγράφουν UserId/TenantId/Entity/Action/RecordId/Status, όχι μυστικά ή passwords.

{% hint style="danger" %}
Το UI δεν πρέπει να χρησιμοποιείται ως fiscal mapping ή για πραγματικές φορολογικές/λογιστικές συναλλαγές. Οι εκκρεμότητες φορολογικής συμβατότητας αντιμετωπίζονται σε ανεξάρτητο βήμα.
{% endhint %}

## 7. CLI — κοινή υπηρεσία με το GUI

**Προσοχή:** Πρόκειται για μεταβολή SQL. Ελέγξτε το ακριβές όνομα της Development βάσης, το Tenant και τις προϋποθέσεις.

Αρχικά `--dry-run`:

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-catalog --username admin --tenant-id "9698df79-3c31-41c9-b292-b7240c7265fb" --confirm-database AenaonERP_Dev --view categories --action create --code FOOD --name "Φαγητά" --dry-run
```

Εφόσον επαληθεύσετε τα στοιχεία, **ρητή εφαρμογή**:

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-catalog --username admin --tenant-id "9698df79-3c31-41c9-b292-b7240c7265fb" --confirm-database AenaonERP_Dev --view categories --action create --code FOOD --name "Φαγητά" --apply
```

Δημιουργία προϊόντος (αντικαταστήστε το `CATEGORY_GUID` με το πραγματικό Id της κατηγορίας):

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-catalog --username admin --tenant-id "9698df79-3c31-41c9-b292-b7240c7265fb" --confirm-database AenaonERP_Dev --view products --action create --category-id "CATEGORY_GUID" --code SKU001 --name "Αναψυκτικό" --tracks-stock --dry-run
```

Μετά τον έλεγχο, αλλάξτε το `--dry-run` σε `--apply`.

Για ενημέρωση: `--action update --id GUID --code ... --name ...` και στα προϊόντα/υπηρεσίες `--category-id GUID`. Για αλλαγή κατάστασης: `--action deactivate --id GUID` ή `--action activate --id GUID` με `--view` και `--apply`.

Ο κωδικός λογαριασμού **ζητείται διαδραστικά** και δεν περνά ποτέ σε command line ή logs. Κάθε write επαληθεύει το πραγματικό DB name, migrations και Owner/Manage.

## 8. Προετοιμασία, εγκατάσταση και έλεγχοι

Από PowerShell:

```powershell
cd "$env:USERPROFILE\Desktop\AENAON-ERP"
git fetch origin
git switch feature/9-4c-catalog-management
dotnet restore AenaonERP.slnx --locked-mode
dotnet format AenaonERP.slnx --verify-no-changes --no-restore
dotnet build AenaonERP.slnx -c Release --no-restore
dotnet test AenaonERP.slnx -c Release --no-build --no-restore --filter "TestCategory!=SqlServer"
dotnet run --project src/Aenaon.Api --launch-profile https
```

Μετά την εκκίνηση, επισκεφτείτε `https://localhost:7140/catalog` και ανοίξτε τις καρτέλες. Αν η εφαρμογή τρέχει ήδη, τερματίστε την πρώτα με `Ctrl+C`.

**Προέλεγχος:** Επιβεβαιώστε ότι οι εφαρμοσμένες migrations παραμένουν πέντε, ο Tenant είναι σωστός και το HTTPS session αντιστοιχεί σε Owner.

**Μετεγχειρητικός έλεγχος:** Επαληθεύστε ότι ο κωδικός εμφανίζεται στον σωστό Tenant, ότι δεν υπάρχουν τιμές/ΦΠΑ, ότι η απενεργοποίηση δεν διαγράφει δεδομένα και ότι τα logs δεν περιέχουν credentials.

## 9. Troubleshooting

| Σύμπτωμα | Πιθανή αιτία / ενέργεια |
| --- | --- |
| Δεν υπάρχει «Νέο...» | Ο χρήστης δεν έχει Owner/Manage· ο Member βλέπει μόνο ανάγνωση |
| «Δεν έχετε δικαίωμα» | Ελέγξτε τον επιλεγμένο Tenant και τη συμμετοχή Owner |
| Η καταχώρηση δεν βρέθηκε | Το Id δεν υπάρχει ή δεν ανήκει στον Tenant/τύπο |
| Υπάρχει ήδη κωδικός | Επιλέξτε διαφορετικό μοναδικό κωδικό της επιχείρησης |
| Δεν υπάρχουν κατηγορίες | Δημιουργήστε πρώτα ενεργή κατηγορία |
| Αποτυχία POST | Ελέγξτε cookie, HTTPS, CSRF token, logs, και όριο 8192 bytes |
| Αποτυχία CLI | Ελέγξτε `--confirm-database`, `--apply`, Owner, interactive terminal |
| Δεν εμφανίζεται αλλαγή | Κάντε νέα αναζήτηση/ανανέωση και ελέγξτε το φίλτρο «ανενεργών» |

## 10. Πότε χρησιμοποιείται / πότε όχι

**Χρησιμοποιείται:** για αρχική δημιουργία εμπορικών κατηγοριών, προϊόντων και υπηρεσιών, διορθώσεις περιγραφών και προσωρινή απενεργοποίηση.

**Δεν χρησιμοποιείται:** για παραστατικά, λογιστική διασύνδεση, φορολογική ταξινόμηση, τιμολογιακή πολιτική, ποσότητες ή warehouse movements.

## 11. Ασφάλεια, backups, logs και rollback

Τα writes επηρεάζουν μόνο τον επιλεγμένο Development Tenant. **Πριν δοκιμές εγγραφών** είναι καλή πρακτική να υπάρχει πρόσφατο backup Development βάσης. Δεν απαιτείται νέα migration.

Εάν το PR πρέπει να αναστραφεί, χρησιμοποιήστε `git revert` του merge και επαναφέρετε την προηγούμενη έκδοση UI/API. **Προσοχή:** Το git rollback **δεν αναιρεί** εγγραφές που ήδη δημιουργήθηκαν στη βάση. Για δεδομένα, εξετάστε τη διατήρησή τους/απενεργοποίηση ή κατάλληλη επαναφορά backup σε απομονωμένο περιβάλλον.

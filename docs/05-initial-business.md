# Aenaon ERP — Αρχική επιχείρηση και κεντρικό κατάστημα

## Σκοπός και σύντομη περιγραφή

Το πέμπτο βήμα καταχωρεί την πρώτη επιχείρηση και ένα κεντρικό κατάστημα στην υπάρχουσα βάση ανάπτυξης. Η προεπισκόπηση εμφανίζει τα επικυρωμένα στοιχεία. Η εφαρμογή αποθηκεύει και τις δύο εγγραφές στην ίδια transaction.

Οι επιχειρησιακοί κανόνες παραμένουν στο Domain. Το νέο `Aenaon.Application` συντονίζει την επικύρωση και την αποθήκευση μέσω interface, ώστε η ίδια υπηρεσία να μπορεί αργότερα να χρησιμοποιηθεί από την παρουσίαση. Το SQL Infrastructure υλοποιεί την πρόσβαση στη βάση. Δεν προστίθενται packages ή νέα migration.

## Προϋποθέσεις και έλεγχοι πριν την εκτέλεση

- Ολοκληρωμένα τα προηγούμενα βήματα, με υπάρχον `ConnectionStrings:Aenaon` στα Development User Secrets.
- Η βάση `AenaonERP_Dev` έχει ενημερωμένο σχήμα, χωρίς εκκρεμείς migrations.
- Οι πίνακες `dbo.Tenants` και `dbo.Stores` είναι κενοί.
- Το SQL login έχει δικαιώματα `SELECT` και `INSERT` στους δύο πίνακες και δυνατότητα χρήσης του transaction application lock.
- Η εφαρμογή εκτελείται με το προφίλ `https` / περιβάλλον Development.

Έλεγχος σχήματος:

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --dry-run
```

{% hint style="info" %}
Η αρχικοποίηση αφορά την πρώτη επιχείρηση σε κενή βάση ανάπτυξης. Το μοντέλο και οι πίνακες υποστηρίζουν πολλές επιχειρήσεις. Η προσθήκη επιπλέον επιχειρήσεων και η πρόσβαση σε δεδομένα από HTTP θα ενταχθούν στη μελλοντική εξουσιοδοτημένη διαχείριση.
{% endhint %}

## 1. Ενημέρωση κώδικα

Σταμάτησε το API με `Ctrl+C` και από τον κεντρικό φάκελο εκτέλεσε:

```powershell
git status
git pull --ff-only origin main
dotnet restore AenaonERP.slnx --locked-mode
```

Διατήρησε δικές σου αλλαγές σε commit ή branch πριν από το pull. Τα User Secrets παραμένουν διαθέσιμα.

## 2. Προεπισκόπηση στοιχείων

Το ακόλουθο παράδειγμα αφορά δοκιμαστική επιχείρηση. Μπορείς να αλλάξεις τα ονόματα πριν από την εκτέλεση:

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --initialize-business --dry-run --tenant-name "Aenaon Demo" --store-code "MAIN" --store-name "Κεντρικό"
```

Αναμενόμενο αποτέλεσμα σε ενημερωμένη, κενή βάση:

```text
Βάση: AenaonERP_Dev
Επιχείρηση: Aenaon Demo
Κατάστημα: MAIN — Κεντρικό
Η προεπισκόπηση ολοκληρώθηκε χωρίς καταχώρηση δεδομένων.
```

Η εντολή επικυρώνει/κανονικοποιεί τα πεδία, ελέγχει το σχήμα και την απουσία επιχειρησιακών δεδομένων. Χρησιμοποιεί προσωρινή transaction και lock για συνεπή έλεγχο, χωρίς `INSERT`, `UPDATE`, `DELETE` ή migrations.

## 3. Εφαρμογή

{% hint style="warning" %}
Η επόμενη εντολή καταχωρεί δεδομένα στην επιλεγμένη βάση. Έλεγξε το όνομα βάσης και τα στοιχεία της προεπισκόπησης. Το `--confirm-database` πρέπει να συμφωνεί ακριβώς με το όνομα στο connection string.
{% endhint %}

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --initialize-business --apply --confirm-database AenaonERP_Dev --tenant-name "Aenaon Demo" --store-code "MAIN" --store-name "Κεντρικό"
```

Σε επιτυχία εμφανίζονται τα στοιχεία, το νέο `TenantId`, το `StoreId` και το μήνυμα:

```text
Η επιχείρηση και το κεντρικό κατάστημα δημιουργήθηκαν επιτυχώς.
```

Κράτησε τα δύο αναγνωριστικά για τον επόμενο έλεγχο. Μια δεύτερη εκτέλεση, ακόμη και με διαφορετικά ονόματα, απορρίπτεται όταν υπάρχουν ήδη επιχειρησιακά δεδομένα. Δεν διαγράφει, δεν μετονομάζει και δεν αντικαθιστά εγγραφές.

## Παράμετροι και πεδία

| Παράμετρος | Περιγραφή |
| --- | --- |
| `--dry-run` | Προεπισκόπηση, χωρίς καταχώρηση. |
| `--apply` | Ρητή καταχώρηση επιχείρησης και καταστήματος. |
| `--confirm-database` | Υποχρεωτική στην εφαρμογή· ακριβές όνομα της ήδη ρυθμισμένης βάσης. |
| `--tenant-name` | Υποχρεωτικό όνομα επιχείρησης, 1–160 χαρακτήρες μετά το trim. |
| `--store-code` | Υποχρεωτικός κωδικός, 1–30 γράμματα/αριθμοί/παύλες/κάτω παύλες. Γίνεται trim και μετατροπή σε κεφαλαία. |
| `--store-name` | Υποχρεωτικό όνομα καταστήματος, 1–160 χαρακτήρες μετά το trim. |

Τα πεδία απορρίπτουν control characters. Η εντολή απαιτεί ακριβώς ένα mode και απορρίπτει άγνωστες/διπλές επιλογές. Τα ονόματα περνούν ως κανονικά arguments, όχι ως SQL. Δεν περιλαμβάνονται credentials στην εντολή.

## 4. Έλεγχοι μετά την καταχώρηση

Στο SSMS, στην ίδια βάση ανάπτυξης:

```sql
SELECT COUNT_BIG(*) AS [TotalTenants] FROM dbo.Tenants;
SELECT COUNT_BIG(*) AS [TotalStores] FROM dbo.Stores;

SELECT t.Id AS [TenantId], t.Name AS [TenantName],
       s.Id AS [StoreId], s.Code AS [StoreCode], s.Name AS [StoreName]
FROM dbo.Tenants AS t
JOIN dbo.Stores AS s ON s.TenantId = t.Id;
```

Αναμένονται μία επιχείρηση, ένα κατάστημα και αναγνωριστικά ίδια με την επιτυχημένη εντολή. Το `TenantId` του καταστήματος συνδέεται με την επιχείρηση. Η αρχικοποίηση δεν αλλάζει το πλήθος εφαρμοσμένων migrations στο ιστορικό.

Μετά την επιτυχία, επανάληψη της αρχικοποίησης ή της προεπισκόπησής της εμφανίζει το μήνυμα ότι υπάρχουν ήδη δεδομένα και exit code `2`. Αυτό είναι ο έλεγχος προστασίας της αρχικής καταχώρησης.

## Ακύρωση, exit codes και logs

Το `Ctrl+C` ζητά ακύρωση. Το συνολικό όριο είναι 30 δευτερόλεπτα, μαζί με τον έλεγχο σχήματος. Η αναμονή για το initialization lock περιορίζεται στα 5 δευτερόλεπτα. Μετά από ακύρωση/timeout έλεγξε τα δεδομένα πριν επαναλάβεις.

| Exit code | Σημασία |
| --- | --- |
| `0` | Επιτυχής προεπισκόπηση ή καταχώρηση. |
| `1` | SQL σφάλμα, timeout ή μη διαθέσιμο initialization lock. |
| `2` | Άκυρα στοιχεία/ορίσματα, ρυθμίσεις, μη ενημερωμένο σχήμα ή ήδη υπάρχοντα δεδομένα. |
| `130` | Ακύρωση από τον χρήστη. |

Τα structured logs περιέχουν το στάδιο, το αποτέλεσμα, τεχνικά IDs και SQL error number. Δεν καταγράφονται ονόματα επιχειρήσεων/καταστημάτων, connection strings, passwords ή exception messages. Η τελική έξοδος CLI εμφανίζει τα στοιχεία που επιβεβαιώνεις τοπικά.

## Ασφάλεια, ταυτόχρονη εκτέλεση και ανάκτηση

Το Infrastructure χρησιμοποιεί αποκλειστικό SQL application lock μέσα σε serializable transaction. Δύο ταυτόχρονες εκτελέσεις της εντολής δεν μπορούν να παρακάμψουν τον έλεγχο κενής βάσης. Η επιχείρηση και το κατάστημα αποθηκεύονται μαζί και το lock αποδεσμεύεται με την ολοκλήρωση/επαναφορά της transaction.

Σε αποτυχία πριν από επιτυχές commit γίνεται rollback. Αν διακοπεί η σύνδεση την ώρα του commit, το αποτέλεσμα μπορεί να χρειάζεται επιβεβαίωση από τη βάση: έλεγξε τα παραπάνω queries, αντί να υποθέσεις αποτυχία ή να επαναλάβεις αυτόματα.

Η εντολή δεν αποτελεί επαναφορά εργοστασιακών ρυθμίσεων ή διαδικασία rename. Σε υπάρχοντα χρήσιμα δεδομένα διατήρησε ελεγμένο backup και χρησιμοποίησε την κατάλληλη διαχείριση/ανάκτηση. Η επιστροφή σε προηγούμενο binary δεν αφαιρεί εγγραφές. Δεν υπάρχει `--force`, αυτόματη διαγραφή ή χειροκίνητη αλλαγή του ιστορικού migrations.

Η λειτουργία επιτρέπεται μόνο στο Development από τον τοπικό λογαριασμό που διαθέτει SQL πρόσβαση. Δεν προστίθεται HTTP business endpoint, διαχειριστής εφαρμογής ή σύστημα login σε αυτό το βήμα. Η παραγωγική αρχικοποίηση και η εξουσιοδότηση θα σχεδιαστούν μαζί με τους χρήστες.

## Αντιμετώπιση προβλημάτων

| Πρόβλημα | Έλεγχος / ενέργεια |
| --- | --- |
| Μη έγκυρο όνομα/κωδικός | Διόρθωσε το πεδίο σύμφωνα με τα όρια και επανέλαβε την προεπισκόπηση. |
| Λάθος επιβεβαίωση βάσης | Χρησιμοποίησε ακριβώς το όνομα της βάσης από την προεπισκόπηση. |
| Μη ενημερωμένο σχήμα | Έλεγξε `--migrate-database --dry-run` και ακολούθησε τον οδηγό του τέταρτου βήματος. |
| Υπάρχουν ήδη δεδομένα | Έλεγξε τα read-only queries. Η εντολή προορίζεται μόνο για κενή βάση. |
| SQL `229` | Έλεγξε δικαιώματα ανάγνωσης/εισαγωγής και χρήσης του application lock στη συγκεκριμένη βάση. |
| SQL `547` | Έλεγξε το σχήμα και τους περιορισμούς της βάσης. Η καταχώρηση δεν ολοκληρώθηκε κανονικά. |
| Busy / timeout | Έλεγξε αν εκτελείται άλλη αρχικοποίηση και την τελική κατάσταση πριν επαναλάβεις. |
| Έξοδος `130` | Η ακύρωση ζητήθηκε· επιβεβαίωσε την κατάσταση στη βάση πριν συνεχίσεις. |

## Έλεγχοι ανάπτυξης και ενημερώσεις

```powershell
dotnet restore AenaonERP.slnx --locked-mode
dotnet build AenaonERP.slnx --configuration Release --no-restore
dotnet test AenaonERP.slnx --configuration Release --no-build --no-restore --filter "TestCategory!=SqlServer"
dotnet publish src/Aenaon.Api --configuration Release --no-restore --self-contained false --output artifacts/api
```

Τα Application tests ελέγχουν επικύρωση πριν από αποθήκευση. Τα API/Infrastructure tests καλύπτουν parsing, confirmation, environment, cancellation και ασφαλή logs. Το SQL CI χρησιμοποιεί ξεχωριστή προσωρινή `AenaonERP_Startup_CI` και ελέγχει preview χωρίς εγγραφές, rollback σε αποτυχία καταστήματος, ταυτόχρονες καταχωρήσεις και επανάληψη χωρίς διπλοεγγραφή. Δεν χρησιμοποιεί την προσωπική βάση ανάπτυξης.

Η δημοσίευση του API δεν εκτελεί την αρχικοποίηση αυτόματα. Σε επόμενες εκδόσεις ακολούθησε τα αντίστοιχα βήματα migrations και deployment, διατηρώντας τα επιχειρησιακά δεδομένα.

# AENAON ERP — Μαζικές Ενέργειες και Εισαγωγή/Εξαγωγή Excel

## Σκοπός
Ενιαίος, επαναχρησιμοποιούμενος μηχανισμός **μαζικών εργασιών** και ασφαλούς **εισαγωγής/εξαγωγής XLSX** για όλες τις επιχειρησιακές οντότητες του AENAON ERP. Αφορά **μελλοντική φάση μετά τη σταθεροποίηση των αντίστοιχων επιχειρησιακών δεδομένων και λειτουργιών**, όχι επόμενο βήμα ανάπτυξης ή ενεργή λειτουργία του PR #47.

{% hint style="info" %}
Η αρχιτεκτονική πρέπει να εξυπηρετεί την ίδια επιχειρησιακή ενέργεια από **Blazor UI**, **CLI** και μελλοντικά **API** μέσω κοινού application service. Οι εργασίες εκτελούνται υποχρεωτικά μέσα στο επιλεγμένο Tenant, με δικαιώματα ρόλων και audit.
{% endhint %}

## Ενδεικτική μορφή προτύπου Excel

Ενιαίο workbook `Aenaon_Import_Template.xlsx` με φύλλα:
- `Categories`: `Code`, `Name`, `ParentCode`, `IsActive`.
- `Items`: `Kind` (Product/Service), `Code`, `Name`, `CategoryCode`, `UnitOfMeasure`, `AccountingType`, `TracksStock`, `IsActive`.
- `PriceLists`: `Code`, `Name`, `StoreCode` (κενό = όλα), `Channel` (All/DineIn/Takeaway/Delivery/Retail/Online), `PricesIncludeVat`, `ValidFrom`, `ValidUntil`, `IsActive`.
- `Prices`: `PriceListCode`, `ItemCode`, `UnitPrice` (EUR, έως 4 δεκαδικά).

Τα φύλλα περιέχουν **κωδικούς επιχειρησιακών οντοτήτων** και όχι εσωτερικά SQL GUID. Για `UnitOfMeasure` και `AccountingType` χρησιμοποιούνται **ακριβώς οι επιτρεπόμενοι enum κωδικοί/συμφωνημένες ετικέτες**, με validation σύμφωνα με `CatalogItem.ValidateCommercial`.

Οι παραπάνω στήλες είναι προδιαγραφή πρώτης έκδοσης, **όχι ήδη διαθέσιμο αρχείο/template ή ενεργό import endpoint**. Πριν την υλοποίηση θα κλειδώσει το schema έκδοσης v1 και θα δημιουργηθούν πραγματικά XLSX templates με παραδείγματα και data validation.

## Ροή εισαγωγής
1. **Επιλογή επιχείρησης/καταστήματος** με server-side δικαιώματα Owner/Manage.
2. **Upload XLSX** μέσω ασφαλούς φόρμας, μέγιστου μεγέθους και ορίου γραμμών (παραμετροποιήσιμα), μόνο επιτρεπόμενος τύπος. Όχι `xlsm`, macros, μη αναμενόμενα external links ή ανεξέλεγκτη αποσυμπίεση ZIP.
3. **Ανάγνωση και αντιστοίχιση** στηλών/φύλλων χωρίς εκτέλεση τύπων Excel και χωρίς άνοιγμα του Microsoft Excel στον server.
4. **Διπλή επικύρωση**: δομική (τύποι, μήκη, κωδικοί, ημερομηνίες `dd/MM/yyyy`, decimals) και domain/SQL (Tenant, FK, μονοσήμαντοι κωδικοί, συμβατά είδη/υπηρεσίες, ενεργοί συσχετισμοί).
5. **Preview/dry-run** με πίνακα `Νέες`, `Ενημερώσεις`, `Χωρίς αλλαγές`, `Παραλείψεις`, `Σφάλματα`, και σαφείς διαφορές ανά πεδίο. Δεν πραγματοποιούνται εγγραφές SQL στο preview.
6. **Πολιτική διπλοτύπων** ανά εισαγωγή: `CreateOnly`, `UpdateExisting` ή `SkipExisting`. Καμία ακούσια αντικατάσταση με κενά πεδία. Τα κενά ποσά **δεν σημαίνουν 0 ή διαγραφή**.
7. **Ρητή επιβεβαίωση** με χρήστη, Tenant, hash αρχείου και token preview· η καταχώρηση απορρίπτεται αν άλλαξε το snapshot ή το αρχείο.
8. **Apply** με κοινές application/domain υπηρεσίες και tenant-scoped συναλλαγές SQL. Ολοκληρώνεται ανά ελεγχόμενη παρτίδα ή ως ενιαία συναλλαγή όταν είναι μικρή. Αποφεύγεται η σιωπηρή μερική καταχώρηση. Περιγράφονται επακριβώς rollback και αποτυχίες.
9. **Αναφορά αποτελεσμάτων**: σύνολα, αριθμοί νέων/αλλαγμένων/απορριφθέντων, αρχείο σφαλμάτων ανά φύλλο-γραμμή-πεδίο. Audit χωρίς secrets.
10. **Ασφαλής επανάληψη** με idempotency key/import job ID, έλεγχο διπλών υποβολών και παρακολούθηση προόδου/ακύρωση στο GUI.

## Σειρά εξαρτήσεων
`Categories → Items → PriceLists → Prices`, ώστε να επιλύονται αναφορές με τους κωδικούς του ίδιου Tenant. Ισχύουν τα πραγματικά Domain constraints:
- Κατηγορία: κωδικός μέχρι 30, όνομα μέχρι 160 χαρακτήρες.
- Είδος: κωδικός μέχρι 40, όνομα μέχρι 200 χαρακτήρες.
- Τιμοκατάλογος: κωδικός μέχρι 30, τίτλος μέχρι 160, νόμισμα EUR.
- Τιμή: μη αρνητικό ποσό και **έως 4 δεκαδικά**, χωρίς αυτόματη φορολογική μετατροπή.
- Ένα είδος τύπου `Service` δεν παρακολουθεί απόθεμα και έχει συμβατή μονάδα/λογιστικό τύπο.

## Μαζικές ενέργειες UI
- Checkbox σε γραμμές και **«Επιλογή όλων των αποτελεσμάτων»** μόνο με ξεκάθαρη διάκριση από την τρέχουσα σελίδα.
- Συγκεντρωτική μπάρα επιλεγμένων, διαθέσιμες ενέργειες βάσει τύπου και δικαιωμάτων, `Escape` για ακύρωση επιλογής.
- Preview διαφορών, επιβεβαίωση για επιπτώσεις και δυνατότητα ασφαλούς ακύρωσης.
- Για αφαίρεση τιμών απαιτείται ρητή επιλογή· για διαγραφή/απενεργοποίηση ισχύουν ξεχωριστοί domain περιορισμοί.
- Διατήρηση επιλογών στα φίλτρα/σελίδες με ανώτατα όρια, προστασία έναντι παρωχημένων τιμών και ενημερωτικό logging.

## Τεχνική αρχιτεκτονική
- `Application`: DTOs, `BulkOperationService`, `ImportPreviewService`, `ImportApplyService`, validation rules και permission policies.
- `Domain`: reuse των ήδη υπαρχόντων invariants (όχι SQL μέσα σε Razor/JS).
- `Infrastructure`: streaming XLSX reader, ασφαλή batch SQL transactions, idempotency και import-job persistence όπου απαιτείται.
- `API/UI`: responsive wizard βημάτων, progress/status, keyboard shortcuts, αρχείο σφαλμάτων.
- `CLI`: εντολές `--import-xlsx --file … --entity … --dry-run` και `--apply --confirm-database …` μέσω των ίδιων υπηρεσιών. Η ακριβής σύνταξη θα καθοριστεί όταν υλοποιηθεί.
- Οι εξαρτήσεις για ανάγνωση/γραφή XLSX πρέπει να επιλεγούν με έλεγχο **τελευταίας stable .NET compatibility, αδειοδότησης και security advisories** πριν γίνει pin NuGet έκδοσης.

## Φορολογική/οικονομική ασφάλεια
- Η εισαγωγή **δεν εκδίδει** παραστατικά και **δεν διαβιβάζει** αυτόματα myDATA/IMPACT.
- Το `PricesIncludeVat` είναι εμπορική ερμηνεία· αλλαγές θέλουν confirmation και **δεν μετατρέπουν** τα amounts.
- Αλλαγές σε λογιστικό τύπο/μονάδα μέτρησης δεν αποδίδουν αυτόματα χαρακτηρισμό Ε3, ΦΠΑ ή τέλη.
- Ιστορικά εκδομένα παραστατικά δεν τροποποιούνται από μαζική εργασία καταλόγου.
- Επαληθεύεται πρώτα SQL backup και rollback strategy για μεγάλες εισαγωγές.

## 1. Σκοπός και σύντομη περιγραφή

Ο Menu Builder επιτρέπει γρήγορη οργάνωση προσχεδίων σε δύο επίπεδα, χωρίς μόνιμη τρίστηλη διάταξη:

1. **Κατηγορίες:** responsive πλέγμα με όνομα, πλήθος ειδών, ένδειξη κρυφής κατηγορίας και διακριτικό μενού ενεργειών.
2. **Είδη κατηγορίας:** δεύτερο πλέγμα με κωδικό/όνομα καταλόγου, προαιρετικό όνομα εμφάνισης, ένδειξη ανενεργού ERP είδους και ενέργειες ανά πλακίδιο.
3. **ERP Catalog:** πτυσσόμενο πάνελ *μέσα* στην προβολή ειδών, για αναζήτηση και σύνδεση επιπλέον ενεργών ειδών.

Το UI ακολουθεί τα χρώματα, τα borders, τα icons και τα Light/Dark themes του AENAON. Δεν αντιγράφει τον σχεδιασμό του Web Estiasis.

## 3. Διαδικασία χρήσης

### 3.1 Αλλαγή και δημιουργία μενού

1. Ανοίξτε **Μενού εστίασης** από το sidebar.
2. Από το πεδίο **Μενού**, επιλέξτε το προσχέδιο και πατήστε **Επιλογή**. Εμφανίζεται το όνομα, ο κωδικός και η αναθεώρησή του.
3. Για νέο μενού, επιλέξτε **Νέο μενού**, εισαγάγετε μοναδικό κωδικό και όνομα και πατήστε **Δημιουργία μενού με είδη ERP**.
4. Οι ενεργές ERP κατηγορίες και τα ενεργά είδη μεταφέρονται από τον server, με τους υφιστάμενους κανόνες και χωρίς αντιγραφή τιμών.
5. Με τη διακριτική ενέργεια **Μετονομασία** αλλάζετε μόνο το όνομα του επιλεγμένου προσχεδίου.

### 3.2 Κατηγορίες

1. Στην αρχική προβολή, επιλέξτε το **πλακίδιο κατηγορίας** για να δείτε τα είδη της.
2. Επιλέξτε **Νέα κατηγορία** για δική σας κατηγορία παρουσίασης. Εισαγάγετε όνομα και πατήστε **Προσθήκη**.
3. Για διαχείριση υπάρχουσας κατηγορίας, ανοίξτε το **γρανάζι** του πλακιδίου. Από εκεί γίνονται μετακίνηση ↑/↓ και επεξεργασία ονόματος/ορατότητας.
4. Η **Αφαίρεση** ενεργοποιείται μόνο σε άδεια κατηγορία και απαιτεί δεύτερη επιβεβαίωση. Αφαιρέστε πρώτα τα είδη, αν χρειάζεται.
5. Η ένδειξη **Κρυφή** δηλώνει `IsVisible=false`. Η απόκρυψη δεν διαγράφει ούτε μεταβάλλει το ERP Catalog.

### 3.3 Είδη κατηγορίας και επιστροφή

1. Πατήστε κατηγορία για την προβολή ειδών.
2. Για επεξεργασία είδους ανοίξτε το **γρανάζι**: ↑/↓ για σειρά, **Όνομα** για προαιρετική ονομασία εμφάνισης ή **Αφαίρεση** με ρητή επιβεβαίωση.
3. Η αφαίρεση αφορά μόνο τη σύνδεση στο προσχέδιο, **ποτέ** το master ERP είδος.
4. Πατήστε **Κατηγορίες** στο breadcrumb για επιστροφή στην αρχική οθόνη.
5. Για χειροκίνητη σύνδεση, επιλέξτε **Από ERP Catalog** ή ανοίξτε **Επιπλέον είδη από ERP Catalog** στο τέλος του πλέγματος. Αναζητήστε με αρχή κωδικού/ονόματος και πατήστε **+** στο κατάλληλο είδος. Τα ήδη συνδεδεμένα εμφανίζονται ως **Προστέθηκε**.

## 4. Πεδία και χειριστήρια

| Πεδίο / ένδειξη | Χρήση | Παρατηρήσεις |
| --- | --- | --- |
| Μενού | Επιλογή προσχεδίου ανά επιχείρηση/κατάστημα | Δεν αλλάζει το default κατάστημα |
| Κωδικός, Όνομα νέου μενού | Δημιουργία νέου draft | Μοναδικότητα κωδικού ελέγχεται στον server |
| Αναθεώρηση | `ExpectedRevision` | Αποτροπή αντικατάστασης ταυτόχρονων αλλαγών |
| Κατηγορία / είδη | Μετάβαση σε επίπεδο πλέγματος | Η διαδρομή διατηρείται στο URL |
| Ορατότητα | Ορατή / Κρυφή | Χωρίς διαγραφή δεδομένων |
| Όνομα εμφάνισης | `NameOverride` | Δεν τροποποιεί την ERP περιγραφή |
| Σειρά ↑/↓ | Μία θέση ανά καταχώριση | Κάθε αλλαγή έχει ξεχωριστή αποθήκευση |
| Αναζήτηση ERP | Μέχρι 50 ενεργά είδη ανά αποτέλεσμα | Προσθήκη μόνο στη συγκεκριμένη κατηγορία |
| Γρανάζι | Δευτερεύουσες ενέργειες ανά πλακίδιο | Διαθέσιμο μόνο σε Owner |

## 5. Συντομεύσεις και προσβασιμότητα

Τα πλακίδια κατηγοριών είναι κανονικοί σύνδεσμοι, τα γρανάζια και οι πτυσσόμενες φόρμες χρησιμοποιούν native `details/summary`, και κάθε POST ενέργεια είναι κανονική HTML φόρμα. **Tab**, **Shift+Tab**, **Enter** και **Space** λειτουργούν σύμφωνα με τη συμπεριφορά του browser. Το ενεργό στοιχείο έχει ορατό focus outline.

- **Alt+M** (εξαρτάται από OS/browser): επιλογή μενού.
- **Alt+F** (εξαρτάται από OS/browser): αναζήτηση στον ERP Catalog όταν εμφανίζεται.
- **Ctrl+S / Cmd+S**: υποβολή έγκυρης φόρμας μόνο όταν το focus βρίσκεται *μέσα* σε φόρμα του Menu Builder.
- Τα κουμπιά ↑/↓ υποστηρίζουν και keyboard· δεν απαιτείται drag-and-drop.

Το layout χρησιμοποιεί CSS auto-fitting grid σε desktop, tablet και mobile, περιλαμβανομένων 320/375/390/768/1366/1920 px. Η πραγματική οπτική αποδοχή σε αυτές τις αναλύσεις, Light/Dark, keyboard και zoom παραμένει **NOT VERIFIED** έως τη δοκιμή σε ενεργό Development browser.

## 6. CLI / CMD

Οι ενέργειες παραμένουν διαθέσιμες μέσω του υπάρχοντος `--manage-menus` και της ίδιας Application service, χωρίς νέα command-line διεπαφή. Ενδεικτική **read-only** εντολή:

~~~powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-menus --username admin --tenant-id "TENANT_GUID" --confirm-database AenaonERP_Dev --action list --dry-run
~~~

Για πλήρη σύνταξη `--dry-run` / `--apply`, revision, exit codes και περιορισμούς δείτε [Manual 61](61-draft-menu-management.md). **Μην εκτελείτε επιπλέον APPLY χωρίς επιβεβαίωση του στόχου και σχετική άδεια.**

## 8. Αντιμετώπιση προβλημάτων

| Σύμπτωμα | Ενέργεια |
| --- | --- |
| Δεν εμφανίζεται μενού | Ελέγξτε επιχείρηση, κατάστημα και επιλογή προσχεδίου |
| Η κατηγορία φαίνεται κενή | Ελέγξτε αν συνδέθηκαν είδη και αν είναι ενεργά στο ERP |
| Δεν εμφανίζεται το γρανάζι | Ελέγξτε ρόλο: ο Member έχει μόνο ανάγνωση |
| Conflict | Ανανέωση, έλεγχος νέας revision, επανάληψη μετά από αναθεώρηση |
| Duplicate | Ελέγξτε αν το είδος είναι ήδη στην κατηγορία |
| Δεν εμφανίζεται νέο ERP είδος | Ελέγξτε ότι η κατηγορία είναι source-linked, το είδος ενεργό και ο server έχει πρόσφατα δεδομένα |
| Φόρμα δεν αποθηκεύει | Ελέγξτε validation, HTTPS, συνεδρία, αντι-CSRF token και logs χωρίς secrets |
| Παλιά διάταξη μετά από update | Ανανεώστε τη σελίδα· τα CSS/JS είναι fingerprinted, χωρίς αλλαγή schema |

## 9. Ασφάλεια, backup και περιορισμοί

Η ανασχεδίαση δεν αλλάζει την Domain/Application/Infrastructure αποθήκευση. Διατηρεί server-side Owner/Member authorization, tenant/store isolation, tenant-scoped SQL FKs, expected revision, idempotency key, antiforgery, HTTPS και server validation. Ορατά HTML πεδία δεν αποτελούν πηγή δικαιωμάτων. Κάθε ενέργεια αποθηκεύεται χωριστά και καταγράφεται από τον υπάρχοντα μηχανισμό.

**Δεν πραγματοποιήθηκε πρόσβαση σε πραγματική Development SQL, παραγωγικό περιβάλλον, νέα migration ή merge στο πλαίσιο του UI redesign.** Κρατήστε ξεχωριστό backup και σχέδιο αποκατάστασης για κάθε μελλοντική εγκεκριμένη DB αλλαγή.

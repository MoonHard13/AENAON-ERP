# AENAON ERP — Διόρθωση ταξινόμησης ειδών τιμοκαταλόγου (PR #54)

## Σκοπός

Η διαχείριση τιμοκαταλόγων ταξινομεί πλέον **όλα τα είδη πριν από τη σελιδοποίηση στον SQL Server**. Οι αριθμητικοί κωδικοί παρουσιάζονται στη φυσική σειρά `1, 2, 3, …, 10`, χωρίς να αλλάζουν οι αποθηκευμένοι κωδικοί, οι τιμές ή οι κανόνες εμπορικής προτεραιότητας.

{% hint style="info" %}
Η αλλαγή είναι **μόνο στον μηχανισμό ανάγνωσης/πλοήγησης** και δεν απαιτεί νέα EF Core migration. Η ήδη εκκρεμής `20261114163000_PriceListAuditHistory` ανήκει στο προηγούμενο βήμα 9.5C.3 και **δεν εφαρμόζεται αυτόματα** από τη λειτουργία sorting.
{% endhint %}

## Σύντομη περιγραφή

Οι επικεφαλίδες στην καρτέλα **Τιμοκατάλογοι → Επιλογή τιμοκαταλόγου → Τιμές προϊόντων και υπηρεσιών** γίνονται προσβάσιμοι σύνδεσμοι. Η ενεργή στήλη εμφανίζει βέλος `↑` ή `↓`. Το δεύτερο κλικ στην ίδια στήλη αντιστρέφει τη σειρά. Όταν επιλέγεται άλλη στήλη, η πρώτη ταξινόμηση είναι αύξουσα. Η επιλογή διατηρείται στις επόμενες σελίδες, στην αναζήτηση και μετά από αποθήκευση/αφαίρεση τιμής.

| Στήλη | Αύξουσα | Φθίνουσα |
| --- | --- | --- |
| Κωδικός | Φυσική αριθμητική σειρά, έπειτα αλφαριθμητικοί κωδικοί | Αντίστροφη φυσική αριθμητική σειρά, έπειτα αλφαριθμητικοί κωδικοί |
| Περιγραφή | Αλφαβητικά Α→Ω | Ω→Α |
| Είδος | Ομαδοποίηση ανά τύπο (Προϊόν/Υπηρεσία) | Αντίστροφη ομαδοποίηση |
| Τιμή μονάδας (€) | Μικρότερη→μεγαλύτερη, κενές τιμές τελευταίες | Μεγαλύτερη→μικρότερη, κενές τιμές τελευταίες |
| Διαχείριση | Χωρίς ορισμένη τιμή πρώτα | Με ορισμένη τιμή πρώτα |

Για κωδικούς με γράμματα ή σύμβολα, εφαρμόζεται η υπάρχουσα ταξινόμηση κειμένου. Η φυσική αριθμητική σύγκριση ισχύει μόνο για κωδικούς αποκλειστικά με ψηφία. Αν δύο εγγραφές έχουν ίδια τιμή ταξινόμησης, χρησιμοποιείται σταθερό αναγνωριστικό για αποφυγή αλλαγής σειράς μεταξύ σελίδων.

## Προαπαιτούμενα

- HTTPS Development εγκατάσταση AENAON ERP, σύνδεση με SQL Server και πρόσβαση σε επιχείρηση/τιμοκατάλογο.
- Tenant Permission `Read` για προβολή και sorting, `Manage` για αποθήκευση τιμών.
- Ενημέρωση κώδικα από το merged PR #54 και επανεκκίνηση του API.
- **Καμία νέα βάση ή migration** για τη διόρθωση αυτή.

## Οδηγίες χρήσης Blazor

1. Από το Back Office επιλέξτε **Τιμοκατάλογοι**, ανοίξτε έναν υπάρχοντα τιμοκατάλογο και αναπτύξτε την ενότητα **Τιμές προϊόντων και υπηρεσιών**.
2. Παρατηρήστε την προεπιλεγμένη στήλη **Κωδικός ↑**. Το σύνολο ταξινομείται `1, 2, …, 10` αντί `1, 10, 2`.
3. Πατήστε στην επικεφαλίδα **Περιγραφή**, **Είδος**, **Τιμή μονάδας (€)** ή **Διαχείριση** για νέα αύξουσα ταξινόμηση. Πατήστε ξανά για φθίνουσα.
4. Αλλάξτε σελίδα ή πραγματοποιήστε αναζήτηση: η ταξινόμηση παραμένει ενεργή, και κάθε νέα επιλογή στήλης επαναφέρει την πρώτη σελίδα των ειδών.
5. Η αποθήκευση/αφαίρεση τιμής ανακατευθύνει στην ίδια αναζήτηση, σελίδα και ταξινόμηση. **Οι μη αποθηκευμένες τιμές δεν διατηρούνται όταν κάνετε κλικ σε σύνδεσμο ταξινόμησης.** Αποθηκεύστε πρώτα τυχόν αλλαγές.

### Πληκτρολόγιο και προσβασιμότητα

Χρησιμοποιήστε `Tab` μέχρι τον σύνδεσμο της επικεφαλίδας και `Enter` για ταξινόμηση. Το ενεργό πεδίο και η κατεύθυνση δηλώνονται μέσω `aria-sort`, το focus είναι εμφανές και η ίδια λειτουργία υποστηρίζεται σε desktop/mobile, Light/Dark. Η αναζήτηση εξακολουθεί να προσφέρει `Alt+Shift+F` όπου το υποστηρίζει ο browser.

## Χρήση CLI

Με πραγματικά αναγνωριστικά, μόνο για ανάγνωση:

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-price-lists --username admin --tenant-id "TENANT_GUID" --confirm-database AenaonERP_Dev --action items --id "PRICE_LIST_GUID" --sort code --page 1 --dry-run
```

Για τιμές από τη μεγαλύτερη στη μικρότερη:

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-price-lists --username admin --tenant-id "TENANT_GUID" --confirm-database AenaonERP_Dev --action items --id "PRICE_LIST_GUID" --sort price --descending --page 1 --dry-run
```

Επιτρεπόμενα `--sort`: `code`, `name`, `kind`, `price`, `priced`. Η `--descending` χρησιμοποιείται μόνο στην ενέργεια `items`, όπως και η `--sort`. Απαιτείται διαδραστική επαλήθευση ταυτότητας. Το `--dry-run` δεν γράφει SQL.

## Πότε χρησιμοποιείται / δεν χρησιμοποιείται

Χρησιμοποιείται για αναζήτηση τιμών, εντοπισμό μη τιμολογημένων προϊόντων/υπηρεσιών, σύγκριση ποσών και σταθερή ανάγνωση σελίδων. **Δεν** αλλάζει το πεδίο `Code`, την εμπορική τιμή, τον επιλεγμένο τιμοκατάλογο σε παραγγελία, τον υπολογισμό ΦΠΑ, το myDATA ή τον IMPACT.

## Έλεγχοι πριν και μετά την ενημέρωση

Πριν από merge, απαιτείται επιτυχές CI (format/build, domain/application/API tests, πραγματικός απομονωμένος SQL Server). Μετά το merge εκτελέστε:

```powershell
git switch main
git pull --ff-only origin main
dotnet restore AenaonERP.slnx --locked-mode
dotnet test AenaonERP.slnx --configuration Release --filter "TestCategory!=SqlServer"
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --dry-run
```

Η κατάσταση migrations **δεν πρέπει να μεταβληθεί εξαιτίας του sorting**. Αν η προηγούμενη 10η migration παραμένει εκκρεμής, θα εξακολουθεί να εμφανίζεται στο dry-run. Σε κάθε περίπτωση αποφεύγουμε επιβολή migration χωρίς ξεχωριστό backup/review.

## Troubleshooting / ασφάλεια / συντήρηση

- **Βλέπω ακόμη `1,10,2`:** βεβαιωθείτε ότι το PR έχει γίνει merge, το `main` ενημερώθηκε και το API επανεκκινήθηκε· επιβεβαιώστε ότι η τρέχουσα ταξινόμηση είναι `Κωδικός ↑`.
- **Το sorting γύρισε στον Κωδικό:** ένας μη επιτρεπτός URL parameter δεν εφαρμόζεται· το UI επιστρέφει ασφαλώς στην προεπιλεγμένη ταξινόμηση. Η CLI απορρίπτει μη έγκυρες παραμέτρους.
- **Δεν βλέπω τη Διαχείριση:** ο χρήστης έχει μόνο δικαίωμα ανάγνωσης ή ο τιμοκατάλογος είναι ανενεργός· οι υπόλοιπες ταξινομήσεις λειτουργούν.
- **Αλλαγές χάθηκαν μετά από κλικ στήλης:** οι κεφαλίδες είναι σύνδεσμοι πλοήγησης. Αποθηκεύστε τις τιμές *πριν* αλλάξετε ταξινόμηση/σελίδα.
- **Σφάλμα SQL:** ελέγξτε τα logs του AENAON χωρίς αποκάλυψη στοιχείων σύνδεσης. Δεν χρειάζονται scripts, ALTER, shrink ή rollback για το sorting.

## Τεχνική αρχιτεκτονική

Η επιτρεπόμενη επιλογή ταξινόμησης επικυρώνεται στο Application layer και αντιστοιχίζεται σε στατικό EF Core LINQ `switch`. Ο SQL Server εφαρμόζει `ORDER BY` πριν από `OFFSET/FETCH`, με υποχρεωτικό TenantId, σταθερό tie-breaker και απομόνωση των τιμών ανά τιμοκατάλογο. Δεν χρησιμοποιούνται δυναμικά `ORDER BY` strings, ακατέργαστο user SQL ή πρόσθετες εξαρτήσεις.

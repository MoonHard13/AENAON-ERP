# AENAON ERP — 9.4C.1: Αύξοντες κωδικοί και ιεραρχικές κατηγορίες

## 1. Σκοπός

Η έκδοση 9.4C.1 βελτιώνει τη διαχείριση καταλόγου εστίασης με **αυτόματο ή χειροκίνητο κωδικό**, **πραγματικές γονικές/θυγατρικές κατηγορίες**, αναζήτηση κατηγοριών από τον SQL Server και ασφαλή επανάληψη αποθήκευσης. Διατηρεί όλες τις δυνατότητες του 9.4C.

{% hint style="warning" %}
Απαιτείται νέα **6η EF Core migration**. Η εφαρμογή **δεν** εφαρμόζει migrations κατά την εκκίνηση. Μη δοκιμάζετε `--apply` χωρίς να επιβεβαιώσετε τη Development βάση `AenaonERP_Dev`, να ελέγξετε προεπισκόπηση και να έχετε πρόσφατο επαληθευμένο backup.
{% endhint %}

## 2. Τι αλλάζει

| Πεδίο | Νέα λειτουργία |
| --- | --- |
| Κωδικός | Αυτόματος ή χειροκίνητος, χωρίς υποχρεωτικά μηδενικά |
| Αυτόματη αρίθμηση | `1`, `2`, `3`, … με ατομική δέσμευση στο SQL transaction |
| Κατηγορίες | Προαιρετική γονική κατηγορία, δυνατότητα πολλών επιπέδων |
| Κατηγορία είδους | Server-side αναζήτηση με πλήρη διαδρομή |
| Διαχείριση | «Αποθήκευση», «Αποθήκευση και νέο», μηνύματα ανά πεδίο |
| Σφάλμα καταχώρισης | Τα πεδία διατηρούνται για έως 10 λεπτά στο προσωρινό server cache του Development |
| Επανάληψη POST | Μοναδικό `RequestId`, αποθήκευση αποτελέσματος στο ίδιο SQL transaction |
| Κατάλογος | Πλήρης διαδρομή κατηγορίας και μετάβαση στις υποκατηγορίες |

## 3. Αρίθμηση 1, 2, 3 — λειτουργικοί κανόνες

- Ο χρήστης επιλέγει **Αυτόματος** (προεπιλεγμένο για νέα εγγραφή) ή **Χειροκίνητος**.
- Στην αυτόματη λειτουργία το πεδίο κωδικού απενεργοποιείται. Ο **τελικός κωδικός εκδίδεται μόνο με την αποθήκευση** και δεν προσφέρεται πρόωρη «κράτηση».
- Η αρίθμηση είναι ανά επιχείρηση και σε δύο ανεξάρτητους χώρους: **κατηγορίες** και **κοινός χώρος προϊόντων/υπηρεσιών**.
- Οι υπάρχοντες κωδικοί `001` και `002` μένουν ακριβώς όπως είναι. Κατά τη migration αναγνωρίζονται ως αριθμοί 1 και 2. Εφόσον είναι οι μεγαλύτεροι αριθμητικοί κωδικοί, ο επόμενος αυτόματος θα είναι **`3`**.
- Οι χειροκίνητοι αριθμητικοί κωδικοί αυξάνουν, όταν χρειάζεται, τον αντίστοιχο μετρητή. Έτσι, αν επιλεγεί χειροκίνητα `100`, ο επόμενος αυτόματος θα είναι `101`.
- Τα κενά στη σειρά είναι αποδεκτά (π.χ. αλλαγή κωδικών/μεταφορά δεδομένων). Η σειρά δεν είναι φορολογική σειρά παραστατικών.
- Ο SQL Server χρησιμοποιεί αποκλειστικό `sp_getapplock` ανά Tenant, μοναδικούς indexes, transaction και durable counter. Η ασφάλεια λειτουργεί και όταν δύο διαφορετικοί υπολογιστές αποθηκεύουν ταυτόχρονα.

{% hint style="info" %}
Οι αριθμοί `1` και `001` είναι **διαφορετικοί αποθηκευμένοι κωδικοί**. Η μετάβαση δεν μετονομάζει τα δεδομένα. Η αρίθμηση σέβεται και τους παλαιότερους αριθμητικούς κωδικούς για τον υπολογισμό του επόμενου αριθμού.
{% endhint %}

## 4. Ιεραρχικές κατηγορίες

Ανοίξτε **Κατάλογος → Κατηγορίες → Νέα κατηγορία**.

1. Επιλέξτε τον τρόπο κωδικού.
2. Συμπληρώστε περιγραφή, π.χ. «ΠΟΤΑ».
3. Στη **Γονική κατηγορία** επιλέξτε «Καμία — κύρια κατηγορία» για νέα ρίζα ή αναζητήστε υπάρχουσα κατηγορία.
4. Επιλέξτε «Αποθήκευση» ή «Αποθήκευση και νέο».
5. Για να μετακινήσετε υπάρχουσα κατηγορία, επιλέξτε «Επεξεργασία», βρείτε νέο γονέα και αποθηκεύστε.

**Παράδειγμα:** ΠΟΤΑ → ΑΝΑΨΥΚΤΙΚΑ → ΧΥΜΟΙ. Τα είδη μπορούν να συνδέονται με οποιαδήποτε ενεργή κατηγορία. Στην επιλογή κατηγορίας εμφανίζεται η πλήρης διαδρομή.

**Διασφαλίσεις:** Ο γονέας πρέπει να είναι ενεργός, να ανήκει στον ίδιο Tenant, να μην είναι η ίδια κατηγορία και να μην δημιουργεί κύκλο. Η εφαρμογή ελέγχει έως 64 επίπεδα. Η απενεργοποίηση κατηγορίας με ενεργά άμεσα παιδιά ή ενεργά είδη απορρίπτεται. Δεν υπάρχει cascade delete. Ο SQL foreign key απαγορεύει αναφορά σε γονέα άλλου Tenant.

Στον Κατάλογο η στήλη κατηγορίας εμφανίζει την πλήρη διαδρομή και ο σύνδεσμος **Υποκατηγορίες** φιλτράρει το επόμενο επίπεδο, με επιστροφή στο «Όλες οι κατηγορίες».

## 5. Αναζητήσιμη επιλογή κατηγορίας

Στη φόρμα προϊόντος, υπηρεσίας και στην επιλογή γονέα:

1. Πληκτρολογήστε στην **Αναζήτηση κατηγορίας**.
2. Η εφαρμογή ζητά έως 30 αποτελέσματα με βάση το πρόθεμα κωδικού ή περιγραφής.
3. Η επιλογή περιλαμβάνει το πλήρες μονοπάτι.
4. Επιλέξτε κατηγορία από τη λίστα. Ο server επαληθεύει ξανά το Tenant και την ενεργή κατάσταση κατά την αποθήκευση.

Η αναζήτηση απαιτεί δικαίωμα **Manage**· δεν εκθέτει ολόκληρο τον πίνακα στο browser. Όταν χαθεί η σύνδεση, οι ήδη φορτωμένες επιλογές διατηρούνται.

## 6. Επεξεργασία και χειρισμός σφαλμάτων

Με **Αποθήκευση και νέο** καταχωρείται το στοιχείο και ανοίγει καθαρή φόρμα του ίδιου τύπου. Το μήνυμα επιτυχίας δείχνει τον πραγματικό κωδικό που αποδόθηκε.

Σε διπλό κωδικό, μη έγκυρη κατηγορία ή μη επιτρεπτή σχέση γονέα, εμφανίζεται σφάλμα και η φόρμα επανέρχεται με τα προηγούμενα πεδία. Η προσωρινή πληροφορία δεσμεύεται στον χρήστη, στο Tenant και στη συγκεκριμένη εγγραφή και **δεν μεταφέρεται στο URL**.

Ταυτόχρονες υποβολές του ίδιου HTML `requestId` επιστρέφουν το ίδιο καταχωρημένο αποτέλεσμα χωρίς να δημιουργούν δεύτερο προϊόν/κατηγορία.

## 7. CLI / CMD

Το CLI χρησιμοποιεί το ίδιο `CatalogWriteService`, επαληθεύει τον κωδικό πρόσβασης στο τερματικό και τη βάση, και απαιτεί Owner/Manage.

**Αυτόματη κατηγορία — προεπισκόπηση:**

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-catalog --username admin --tenant-id 9698df79-3c31-41c9-b292-b7240c7265fb --confirm-database AenaonERP_Dev --view categories --action create --name "ΠΟΤΑ" --auto-code --dry-run
```

**Αυτόματη κατηγορία — εγγραφή μόνο μετά τον έλεγχο:**

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-catalog --username admin --tenant-id 9698df79-3c31-41c9-b292-b7240c7265fb --confirm-database AenaonERP_Dev --view categories --action create --name "ΠΟΤΑ" --auto-code --apply
```

**Υποκατηγορία με χειροκίνητο κωδικό:**

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --manage-catalog --username admin --tenant-id 9698df79-3c31-41c9-b292-b7240c7265fb --confirm-database AenaonERP_Dev --view categories --action create --code DRINKS --name "ΑΝΑΨΥΚΤΙΚΑ" --parent-category-id "PARENT_GUID" --dry-run
```

Για πραγματικό `--apply`, αντικαταστήστε το `PARENT_GUID` με έγκυρο αναγνωριστικό γονέα και ελέγξτε πρώτα `--dry-run`. Το `--root` στην ενημέρωση κατηγορίας την επαναφέρει στην κορυφή· αν παραλειφθούν και `--root` και `--parent-category-id`, διατηρείται ο υπάρχων γονέας.

**Προσοχή:** Το `--dry-run` **δεν δεσμεύει αριθμό** ούτε υποκαθιστά τον τελικό SQL έλεγχο. Η πραγματική δέσμευση γίνεται μόνο με `--apply`.

## 8. Εγκατάσταση, migration preview, backup και εφαρμογή

### 8.1 Έλεγχος source / build

```powershell
cd "$env:USERPROFILE\Desktop\AENAON-ERP"
git fetch origin
git switch feature/9-4c-1-hierarchical-catalog-autocodes
dotnet restore AenaonERP.slnx --locked-mode
dotnet format AenaonERP.slnx --verify-no-changes --no-restore
dotnet build AenaonERP.slnx -c Release --no-restore
dotnet test AenaonERP.slnx -c Release --no-build --no-restore --filter "TestCategory!=SqlServer"
```

### 8.2 Προεπισκόπηση (καμία SQL αλλαγή)

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --dry-run
```

Αναμένονται **5 εφαρμοσμένες και 1 εκκρεμής** migration:

`20261112130000_CatalogHierarchyAndNumbering`.

### 8.3 Backup — πριν από οποιαδήποτε εφαρμογή

Πάρτε πλήρες backup της βάσης Development με εγκεκριμένη διαδικασία της εταιρείας. Επιβεβαιώστε τη δυνατότητα αποκατάστασης σε ξεχωριστή βάση/instance. Πριν την εφαρμογή, καταγράψτε πόσες γραμμές υπάρχουν ήδη στους `dbo.CatalogCategories` και `dbo.CatalogItems`.

{% hint style="danger" %}
Μην εφαρμόζετε migration σε παραγωγική βάση. Η αντίστροφη migration `Down` αφαιρεί τον γονέα/μετρητές και επομένως **δεν αποτελεί ασφαλή επαναφορά δεδομένων**. Για rollback απαιτείται σχέδιο αποκατάστασης.
{% endhint %}

### 8.4 Εφαρμογή (μόνο με ρητή έγκριση στον Development SQL Server)

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --migrate-database --apply --confirm-database AenaonERP_Dev
```

**Η εντολή παρατίθεται για τον διαχειριστή. Δεν εκτελείται αυτόματα από τη λειτουργία ανάγνωσης ή το PR.** Μετά την εφαρμογή, η προεπισκόπηση αναμένει 6 applied και 0 pending.

### 8.5 Άνοιγμα UI

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https
```

Διεύθυνση: `https://localhost:7140/catalog`. Κάντε `Ctrl+F5` μετά την πρώτη εκκίνηση.

## 11. Troubleshooting

| Πρόβλημα | Ενέργεια |
| --- | --- |
| Το Back Office δεν ξεκινά | Ελέγξτε `--migrate-database --dry-run` και τη διαθεσιμότητα του SQL |
| Το auto-code δίνει 3 αντί 1 | Υπάρχουν ήδη αριθμητικοί κωδικοί (π.χ. 001,002) |
| Διπλός χειροκίνητος κωδικός | Αλλάξτε κωδικό ή επιλέξτε αυτόματο |
| Η κατηγορία δεν εμφανίζεται στο dropdown | Αναζητήστε με πρόθεμα· απαιτείται ενεργή κατηγορία/Manage |
| Απόρριψη γονέα | Ελέγξτε ενεργή κατάσταση, ίδιο Tenant και απουσία κύκλου |
| Αδυναμία απενεργοποίησης | Υπάρχουν ενεργές υποκατηγορίες ή είδη |
| Η φόρμα χάθηκε μετά από επανεκκίνηση | Τα drafts βρίσκονται προσωρινά στη μνήμη, όχι στη βάση |
| Διπλή δημιουργία λόγω refresh | Ελέγξτε τα server logs και το requestId, χωρίς χειροκίνητη διαγραφή |

## 12. Ασφάλεια και περιορισμοί

Οι λειτουργίες παραμένουν Development-only και η εξουσιοδότηση βασίζεται στο υπάρχον HTTPS cookie, Anti-CSRF, Owner/Manage και tenant-scoped SQL. Τα δομημένα logs καταγράφουν μεταβολές και απορρίψεις χωρίς κωδικούς πρόσβασης ή ευαίσθητα δεδομένα φόρμας. Δεν υπάρχει νέο πακέτο NuGet.

**Δεν εισάγονται** τιμές, ΦΠΑ, φορολογικοί χαρακτηρισμοί, συνδυασμοί myDATA/IMPACT, έκδοση παραστατικών ή κινήσεις αποθήκης. Οι προηγούμενες εκκρεμότητες myDATA/IMPACT παραμένουν χωριστό gate.

## 13. Πότε χρησιμοποιείται / πότε όχι

**Χρησιμοποιείται** κατά τη ρύθμιση πραγματικού εμπορικού καταλόγου και μαζική εισαγωγή κατηγοριών/ειδών.

**Δεν χρησιμοποιείται** για φορολογική αρίθμηση παραστατικών, διαχείριση αποθήκης, τιμοκατάλογο ή παραγωγικές συναλλαγές.

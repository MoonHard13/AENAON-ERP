# AENAON ERP — 9.4C.4: Ταξινόμηση Καταλόγου (Sorting)

## 1. Σκοπός

Στο βίντεο ελέγχου της **13/11/2026**, ο πίνακας καταλόγου παρουσιάζει κωδικούς, περιγραφές, κατηγορίες, τύπο, παρακολούθηση αποθέματος και κατάσταση, αλλά δεν επιτρέπει αλλαγή της σειράς. Το βήμα 9.4C.4 προσθέτει **server-side ταξινόμηση** με προσβάσιμες επικεφαλίδες σε προϊόντα, υπηρεσίες και κατηγορίες.

{% hint style="info" %}
Η ταξινόμηση είναι **μόνο για ανάγνωση**. Δεν αλλάζει κωδικούς, τιμές, αποθέματα, κατηγορίες ή την αποθηκευμένη σειρά στη βάση. **Δεν απαιτείται νέα migration** και δεν επηρεάζονται myDATA/IMPACT ή έκδοση παραστατικών.
{% endhint %}

## 2. Προϋποθέσεις

- AENAON ERP Development, branch `feature/9-4c-4-catalog-server-sorting`.
- .NET SDK που προβλέπει το `global.json` (10.0.404 στο συγκεκριμένο Development περιβάλλον).
- SQL Server 2022, `AenaonERP_Dev` με τις 6 ήδη εφαρμοσμένες migrations.
- Ενεργό HTTPS και σύνδεση στον σωστό Tenant/Store.
- Δικαίωμα **Read** (Owner ή Member), χωρίς ανάγκη για πρόσβαση Manage.

## 3. Χρήση από το Back Office

1. Ανοίξτε **Κατάλογος** και την ενότητα **Προϊόντα**, **Υπηρεσίες** ή **Κατηγορίες**.
2. Πατήστε την επικεφαλίδα μιας στήλης που διαθέτει βέλος **↕**.
3. Η πρώτη επιλογή στήλης ταξινομεί **αύξουσα (↑)**. Το δεύτερο πάτημα στην ίδια επικεφαλίδα αλλάζει σε **φθίνουσα (↓)**. Αν αλλάξετε στήλη, αρχίζει από αύξουσα.
4. Η ενεργή στήλη έχει διακριτή επισήμανση και το βέλος δείχνει την τρέχουσα κατεύθυνση.
5. Η εφαρμογή επιστρέφει στη **σελίδα 1** όταν επιλέγετε νέα σειρά. Η επόμενη/προηγούμενη σελίδα διατηρεί το sort.
6. Η αναζήτηση, η εμφάνιση ανενεργών, οι εγγραφές ανά σελίδα και το επιλεγμένο Tenant/Store διατηρούνται.
7. Ο σύνδεσμος **Καθαρισμός** επαναφέρει και τη βασική σειρά κωδικού.

### 3.1 Στήλες προϊόντων και υπηρεσιών

| Στήλη | Κριτήριο |
| --- | --- |
| Κωδικός | Αριθμητική αύξουσα/φθίνουσα σειρά για καθαρά αριθμητικούς κωδικούς· αλφαριθμητικοί ακολουθούν |
| Περιγραφή | Αλφαβητική σειρά κατά την collation του SQL Server |
| Κατηγορία | Αλφαβητική σειρά ονόματος κατηγορίας |
| Τύπος | Προϊόν / Υπηρεσία (στα χωριστά tabs ο τύπος είναι σταθερός) |
| Απόθεμα | Όχι / Ναι με εναλλαγή |
| Κατάσταση | Ανενεργό / Ενεργό με εναλλαγή |

Οι στήλες **Ενέργειες** δεν ταξινομούνται.

### 3.2 Στήλες κατηγοριών

Ταξινόμηση κατά **Κωδικό**, **Κατηγορία (όνομα)** και **Κατάσταση**. Όταν προβάλλετε υποκατηγορίες συγκεκριμένου γονέα, το φίλτρο `parentId` διατηρείται. Οι ενέργειες ανάπτυξης υποκατηγοριών δεν αλλάζουν τους κανόνες ταξινόμησης της κύριας λίστας.

## 4. Αριθμητικοί κωδικοί

Η SQL ταξινομεί τους **καθαρά αριθμητικούς κωδικούς έως 18 ψηφία** με ασφαλή μετατροπή σε `bigint`: `1, 2, 3, 9, 10, 11`, όχι `1, 10, 11, 2`. Έτσι οι παλιές μορφές `001` και `002` έχουν τιμές 1 και 2 κατά την ταξινόμηση, χωρίς να αλλάζουν στη βάση. Για ισότιμες αριθμητικές τιμές (π.χ. `1` και `001`) εφαρμόζεται σταθερή δευτερεύουσα σειρά κωδικού και ID. Οι αλφαριθμητικοί κωδικοί εμφανίζονται μετά τους αριθμητικούς και ακολουθούν τη γλωσσική σειρά της SQL collation.

{% hint style="warning" %}
Για αριθμητικές συμβολοσειρές **με περισσότερα από 18 ψηφία**, αποφεύγεται η μετατροπή σε `bigint` ώστε να μην προκύπτει overflow· αυτές ταξινομούνται με μήκος και αλφαβητικό tie-breaker. Η εφαρμογή δεν μεταβάλλει ποτέ τη μορφή των κωδικών.
{% endhint %}

## 5. Τεχνική ασφάλεια

- Το `CatalogReadQuery` δέχεται **μόνο** γνωστά sort keys (`code`, `name`, `category`, `kind`, `stock`, `status`). Οι κατηγορίες δέχονται μόνο `code`, `name`, `status`.
- Η SQL υλοποίηση χρησιμοποιεί αποκλειστικά **EF Core LINQ expressions**, χωρίς δυναμικό SQL ή concatenated `ORDER BY`.
- Υποχρεωτικό tenant-scoped `Where(TenantId)`, σύνθετο join για κατηγορίες και σταθερό `Id` tie-breaker.
- Η σειρά υπολογίζεται **πριν από το `Skip/Take`**, οπότε ισχύει σε ολόκληρο το αποτέλεσμα και όχι μόνο στις ορατές γραμμές.
- Όριο σελίδας και μεγέθους παραμένει ενεργό. Τα εξουσιοδοτημένα Member accounts έχουν το ίδιο read-only sorting.
- Τα URLs περιλαμβάνουν κλειδιά όπως `sort=name&desc=true` και διατηρούν τα ήδη υπάρχοντα φίλτρα.

## 6. Πληκτρολόγιο και προσβασιμότητα

Οι κεφαλίδες είναι πραγματικοί σύνδεσμοι, ενεργοποιούνται με `Tab` και `Enter`. Η ενεργή κεφαλίδα δηλώνεται με `aria-sort="ascending"` ή `aria-sort="descending"`. Η προσβάσιμη ετικέτα περιγράφει τι θα γίνει στο επόμενο πάτημα. Ο πίνακας παραμένει οριζόντια κυλιόμενος σε μικρό παράθυρο και σε browser zoom 150–250%.

## 7. Εγκατάσταση σε Development

Σταματήστε το προηγούμενο instance του API με `Ctrl+C`, έπειτα:

```powershell
cd "$env:USERPROFILE\Desktop\AENAON-ERP"
git status --short
git fetch origin
git switch feature/9-4c-4-catalog-server-sorting
git pull --ff-only origin feature/9-4c-4-catalog-server-sorting

dotnet restore AenaonERP.slnx --locked-mode
dotnet build AenaonERP.slnx -c Release --no-restore
dotnet test AenaonERP.slnx -c Release --no-build --no-restore --filter "TestCategory!=SqlServer"
dotnet run --project src/Aenaon.Api --launch-profile https
```

Ανοίξτε `https://localhost:7140/catalog`. Εάν χρειαστεί, χρησιμοποιήστε `Ctrl+Shift+R` στον Chrome. **Μη χρησιμοποιήσετε `--migrate-database --apply`**· η αλλαγή δεν έχει migration.

## 9. Troubleshooting

| Σύμπτωμα | Ενέργεια |
| --- | --- |
| Οι επικεφαλίδες δεν είναι clickable | Ελέγξτε ότι τρέχει το σωστό branch και φορτώνει το νέο Razor/CSS μέσω επανεκκίνησης API. |
| Αλλαγή sorting επιστρέφει σε σφάλμα φίλτρων | Ελέγξτε τα URL query parameters `sort` και `desc`. Μόνο γνωστές τιμές επιτρέπονται. |
| Οι σελίδες επαναλαμβάνουν εγγραφές | Ελέγξτε ότι η SQL σειρά προηγείται του `Skip/Take` και υπάρχει `ThenBy(Id)`. |
| Η σειρά ελληνικών κειμένων διαφέρει | Ελέγξτε την SQL Server collation. Η ταξινόμηση ακολουθεί τη collation της βάσης και όχι το locale του browser. |
| Το sort δεν εφαρμόζεται με Member | Ελέγξτε το `TenantPermission.Read` και τα structured logs της εφαρμογής. |

## 10. Logging, backup, rollback

Το structured logging καταγράφει πλέον `SortBy` και `Descending` μαζί με Tenant, view, page και page size, χωρίς να αποθηκεύει μυστικά. Η ταξινόμηση είναι read-only, επομένως δεν χρειάζεται migration ή schema backup για την ίδια την αλλαγή. Σε περίπτωση προβλήματος, κάντε revert του PR/commit και επανεκκινήστε το API. Δεν απαιτείται `Down` migration.

Για δοκιμές νέων εγγραφών στον Development κατάλογο, διατηρήστε το ήδη συμφωνημένο backup της βάσης.

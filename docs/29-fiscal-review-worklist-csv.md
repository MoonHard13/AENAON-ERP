# Aenaon ERP — Βήμα 9.3C.3B.5A: Λίστα Ανθρώπινου Φορολογικού Ελέγχου σε CSV

## 1. Σκοπός

Το `Fiscal Semantic Review Triage` του βήματος 9.3C.3B.4 δημιούργησε ένα JSON με **254 εκκρεμείς παρατηρήσεις** από το αρχείο συνδυασμών χαρακτηρισμών της ΑΑΔΕ. Το παρόν βήμα εξάγει μια **οργανωμένη λίστα εργασίας για φοροτεχνικό και τεχνικό reviewer** σε Excel-compatible CSV (UTF-8 με BOM και `sep=;`).

Το CSV διατηρεί σταθερό `EvidenceId`, SHA-256, φύλλο, διεύθυνση κελιού, κατεύθυνση (έσοδα/έξοδα), κατηγορία οδηγίας, προτεραιότητα και ερώτημα ανθρώπινου ελέγχου. Προσθέτει **κενά πεδία τεκμηρίωσης** για να χρησιμοποιηθεί ως φύλλο εργασίας.

{% hint style="danger" %}
**Καμία ανθρώπινη απόφαση δεν καταχωρίζεται ή επικυρώνεται από το ERP.** Η προεπιλεγμένη τιμή κάθε γραμμής είναι `Pending`. Ακόμη και αν κάποιος αλλάξει με το χέρι το CSV, **δεν υπάρχει import, approval API, SQL write, tenant authorization ή ενεργός fiscal rule engine**. Οι ιδιωτικές σημειώσεις στο CSV δεν αποτελούν ψηφιακά υπογεγραμμένη απόφαση.
{% endhint %}

## 3. Προϋποθέσεις

- Windows, ενεργό περιβάλλον **Development** και έκδοση .NET SDK **10.0.404** όπως ορίζεται στο `global.json`.
- Εγκατεστημένο Aenaon ERP από το PR αυτού του βήματος, χωρίς τοπικές μη συγχρονισμένες αλλαγές.
- Πρωτότυπο XLSX ΑΑΔΕ και αμετάβλητο `AADE_myDATA_FullEvidence.json` στον φάκελο `C:\FiscalEvidence\`, εκτός repository.
- Δικαιώματα ανάγνωσης των δύο τεκμηρίων και δημιουργίας νέου CSV στον επιλεγμένο φάκελο.
- Το review CSV πρέπει να φυλάσσεται με ελεγχόμενη πρόσβαση, επειδή ενδέχεται να προστεθούν ονόματα/σημειώσεις από reviewers.

## 5. Δημιουργία της λίστας εργασίας

```powershell
dotnet run --project src/Aenaon.Api --launch-profile https -- --triage-fiscal-semantics --evidence-file "C:\FiscalEvidence\syndiasmoi_xaraktirismwn_v2.0.2_0.xlsx" --evidence-json "C:\FiscalEvidence\AADE_myDATA_FullEvidence.json" --worklist-csv "C:\FiscalEvidence\AADE_Review_Worklist_Pending.csv"
```

Το CLI πρώτα **επαληθεύει ξανά** το πλήρες JSON έναντι του πραγματικού XLSX, όπως στο βήμα 9.3C.3B.3. Έπειτα ταξινομεί τις εκκρεμότητες με το ίδιο service του 9.3C.3B.4 και εξάγει το CSV. Καμία σιωπηρή παράκαμψη αυτής της επαλήθευσης δεν επιτρέπεται.

Αναμενόμενη μορφή αποτελέσματος για το συγκεκριμένο πρωτότυπο:

```text
ΤΕΧΝΙΚΗ ΣΥΜΦΩΝΙΑ XLSX / JSON: ΕΠΙΤΥΧΗΣ
...
Μη εγκεκριμένα υποψήφια ζεύγη: 1403
Ανοιχτές παρατηρήσεις: 254
...
Νέα λίστα Excel για ανθρώπινο έλεγχο: C:\FiscalEvidence\AADE_Review_Worklist_Pending.csv
Το CSV είναι για χειροκίνητες σημειώσεις· ΔΕΝ αποτελεί εισαγωγή εγκρίσεων.
```

Η εντολή δέχεται **ένα** από `--report-json` ή `--worklist-csv`, όχι και τα δύο στην ίδια εκτέλεση. Διατηρείται πλήρως η προηγούμενη χρήση του `--report-json`.

{% hint style="warning" %}
Δεν αντικαθίσταται υπάρχον CSV. Εάν έχεις ήδη το `AADE_Review_Worklist_Pending.csv`, χρησιμοποίησε νέο όνομα, π.χ. `AADE_Review_Worklist_Pending_v2.csv`. Μην διαγράφεις τις προηγούμενες χειροκίνητες σημειώσεις.
{% endhint %}

## 6. Άνοιγμα στο Microsoft Excel

1. Άνοιξε τον φάκελο `C:\FiscalEvidence`.
2. Επίλεξε το νέο CSV και άνοιξέ το με Excel.
3. Η πρώτη γραμμή `sep=;` δηλώνει **ερωτηματικό** ως διαχωριστικό για συμβατότητα με τις ελληνικές τοπικές ρυθμίσεις.
4. Έλεγξε ότι οι στήλες διαχωρίζονται σωστά και ότι οι ελληνικοί χαρακτήρες εμφανίζονται κανονικά.
5. Χρησιμοποίησε φίλτρα ή ταξινόμηση στη στήλη `Priority`: πρώτα **Critical**, μετά **High**, στη συνέχεια **Normal**.
6. Πρόσθεσε σημειώσεις μόνο στα **κενά πεδία ανθρώπινου ελέγχου**. Μην αλλάξεις `EvidenceId`, `OriginalXlsxSha256`, `Sheet`, `Address`, `Direction` ή κείμενο τεκμηρίου.

Εναλλακτικά, για εξαγωγή σε Excel Workbook `.xlsx`, χρησιμοποίησε «Αποθήκευση ως» **σε νέο αρχείο**, κρατώντας και το αμετάβλητο αρχικό CSV.

## 7. Πεδία CSV

| Στήλη | Χρήση |
| --- | --- |
| `EvidenceId` | Μοναδικό αναγνωριστικό της συγκεκριμένης εκκρεμότητας |
| `OriginalXlsxSha256` | Δέσμευση στο ακριβές πρωτότυπο XLSX |
| `Sheet`, `Address`, `Direction` | Ακριβής αναφορά σε φύλλο, κελί και πλευρά εσόδου/εξόδου |
| `SuggestedKind`, `Priority` | Μη δεσμευτική τεχνική ταξινόμηση/προτεραιότητα |
| `ExactText_ExcelSafe` | Κείμενο κελιού για ασφαλή **προβολή** στο Excel |
| `OriginalReason`, `RequiredHumanCheck` | Τεχνική αιτία και ερώτημα που πρέπει να εξεταστεί |
| `NearbyCells_ExcelSafe` | Πραγματικά γειτονικά κελιά (βοηθητικό context) |
| `ReviewerStatus` | Αρχικά **Pending**· δεν υπάρχει διαδικασία εισαγωγής έγκρισης |
| `ReviewerNotes` | Ελεύθερη τεκμηρίωση ανθρώπινου ελέγχου |
| `AadeSourceUrlAndSection` | Επίσημο URL ΑΑΔΕ και ενότητα που στηρίζει την ερμηνεία |
| `ImpactSourceUrlAndSection` | Επίσημο URL IMPACT και ενότητα που στηρίζει τη συμβατότητα |
| `ReviewedBy`, `ReviewedAtUtc` | Δήλωση reviewer και UTC χρόνου — **όχι επαληθευμένη ταυτότητα ή υπογραφή** |

{% hint style="info" %}
Για λόγους προστασίας από **CSV/Excel formula injection**, τιμές πρωτοτύπου που θα μπορούσαν να ερμηνευτούν ως τύποι Excel εμφανίζονται με πρόθεμα ασφαλείας. Η ακριβής αυθεντική τιμή παραμένει **αμετάβλητη στο πρωτότυπο XLSX και στο JSON τεκμηρίου**. Μη χρησιμοποιείς το Excel-safe κείμενο ως φορολογική πηγή.
{% endhint %}

## 8. Διαδικασία ανθρώπινου ελέγχου

Για κάθε παρατήρηση:

1. Άνοιξε το ακριβές `Sheet!Address` στο πρωτότυπο XLSX με το δηλωμένο SHA-256.
2. Επιθεώρησε τα συγχωνευμένα κελιά, τη μορφοποίηση και τα συμφραζόμενα — όχι μόνο το περιεχόμενο της μεμονωμένης γραμμής.
3. Ερμήνευσε την οδηγία σε σχέση με τον τύπο παραστατικού, την προηγούμενη/επόμενη χρήση, τον σχετικό MARK ή τη στήλη ΣΤ.9, όπου εφαρμόζεται.
4. Άνοιξε την τρέχουσα τεκμηρίωση ΑΑΔΕ και IMPACT, πρόσθεσε **συγκεκριμένα links/ενότητες** και κατέγραψε τυχόν αβεβαιότητες.
5. Για ΦΠΑ, εξαιρέσεις, B2G ή ειδική διακίνηση, χρειάζεται επιπλέον ανεξάρτητος έλεγχος πλήρους payload.
6. Σημείωσε τα συμπεράσματα στις κενές στήλες, χωρίς να προϋποθέτεις αποδοχή από το ERP.
7. Η πραγματική καταχώρηση απόφασης με έλεγχο ρόλων, διαχωρισμό αρμοδιοτήτων, audit και versioned approvals απαιτεί **ξεχωριστή υλοποίηση και ρητή εξουσιοδότηση**.

## 9. Έλεγχοι ασφαλείας

- **Read-only** επαναξιολόγηση XLSX και πλήρους JSON, χωρίς αλλαγή στο πρωτότυπο.
- Μόνη προαιρετική εγγραφή: **νέο CSV**, ποτέ SQL/Provider/myDATA request.
- UTF-8 με BOM για συμβατότητα ελληνικού Excel.
- Κωδικοποίηση ειδικών χαρακτήρων CSV και μετριασμός Excel formula injection.
- `FileMode.CreateNew`, ώστε να μην καταστραφούν παλιές σημειώσεις· προσπάθεια διαγραφής μερικώς γραμμένου **νέου** CSV αν αποτύχει η διαδικασία.
- Καμία παραγωγική ενεργοποίηση, νέα migration, package dependency ή αλλαγή tenant δικαιωμάτων.
- Τα logs περιέχουν μόνο counts, statuses και error codes, όχι κείμενα τεκμηρίων.

## 10. Troubleshooting και κωδικοί εξόδου

| Πρόβλημα | Επίλυση |
| --- | --- |
| `fiscal.xlsx.reconciliation.mismatch` | Το JSON δεν συμφωνεί πλέον με το αρχικό XLSX: έλεγξε SHA-256/πραγματικά αρχεία |
| `fiscal.semantics.worklist.path.invalid` | Χρησιμοποίησε νέα διαδρομή `.csv` |
| `fiscal.semantics.worklist.invalid` | Ο φάκελος έχει διπλά Evidence IDs, μη πλήρη groups ή στοιχεία που εμφανίζονται ως εγκεκριμένα |
| Το CSV υπάρχει ήδη | Αποθήκευσε με νέο όνομα· μην κάνεις overwrite |
| Περίεργη εμφάνιση τιμών Excel | Έλεγξε UTF-8 και τον χαρακτήρα `sep=;`; το αρχικό XLSX/JSON παραμένει αυθεντία |
| Οι παρατηρήσεις δεν γίνονται `Approved` | Αναμενόμενο: δεν έχει υλοποιηθεί ασφαλής διαδικασία approval |

CLI exit codes: `0` επιτυχής εξαγωγή **Pending** worklist, `1` σφάλμα αρχείων, `2` άκυρα τεκμήρια ή ορίσματα, `130` ακύρωση με `Ctrl+C`.

## 11. Backup / rollback / ενημέρωση

- Κράτησε πρωτότυπο XLSX, πλήρες JSON, semantic review JSON και το νέο CSV σε προστατευμένο φάκελο, με κατάλληλα αντίγραφα ασφαλείας.
- Κατά την επεξεργασία του CSV, αποθήκευε **νέα αρχεία έκδοσης**. Μην επανεξάγεις πάνω σε υπάρχουσες σημειώσεις.
- Για άλλη έκδοση ΑΑΔΕ, επανάλαβε λήψη, hash, πλήρη JSON, τεχνική συμφωνία και νέα λίστα review.
- Rollback του κώδικα με Git revert, **χωρίς SQL migration**.
- Η ενεργοποίηση τιμολόγησης παραμένει απαγορευμένη μέχρι να υπάρξουν εγκεκριμένες, επαληθευμένες και εξουσιοδοτημένες ροές.
